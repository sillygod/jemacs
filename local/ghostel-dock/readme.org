#+TITLE: ghostel-dock

A project's Ghostel terminals, named, in one place: a bottom panel that
=SPC '= shows and hides, and a manager overlay on =SPC b t= that lists
every project's terminals with what each one is doing.  A ghostel-cmd
command can name its terminal (=npm run dev= → =dev=), and a project's
terminals come back after an Emacs restart.

* The panel

| Key        | Action                                                          |
|------------+-----------------------------------------------------------------|
| =SPC '=    | Show the panel with this project's last-used terminal, selected |
|            | (a new =shell= when there is none); shown, hide it.  From a     |
|            | terminal the leader is =M-m=: =M-m '=.                          |
| =C-u SPC '= | Start another terminal in the project; asks its name           |

- A bottom side window, =ghostel-dock-height= high (0.3 of the frame, or
  a number of lines), marked with the window parameter =ghostel-dock=.
  Hiding it deletes the side window: the other windows get their room
  back and keep their buffers; no split is left.
- "Last used" is =buffer-list= order: the terminal of the project most
  recently selected.  Showing one in the panel without selecting it (a
  preview) does not change it.
- A terminal shows in one window: showing it in the panel takes it out
  of a main window that showed it, which goes back to its previous
  buffer.  Ghostel would otherwise size it for two windows.
- Starting a terminal never moves the focus by itself (ghostel pops to
  what it starts; the dock gives the focus back): =SPC TAB= started a
  terminal and the file stays selected.

* Names and what belongs to a project

- A terminal is =*PROJECT:NAME*= (=*web:dev*=); a remote project's is
  =*PROJECT@HOST:NAME*=.  The name of the directory is the project's.
- It belongs to its /root/: the project's root when it was made, or the
  directory it started in outside a project.  Kept in the buffer-local
  =ghostel-dock--root=, so a =cd= does not move it.
- Terminals made before the dock are found too and keep their names:
  ghostel's =*PROJECT-ghostel*= and its =C-u= siblings
  =*PROJECT-ghostel*<2>= belong to the project their name says, even
  after a =cd= away (by name against =project-known-project-roots=);
  anything else to the project of its directory.  Recorded at the first
  look.  =r= in the manager gives one a dock name if wanted.
- Not terminals: a ghostherd agent's buffer -- ghostherd sets
  =ghostherd-session-id= in every buffer it shows an agent in, on both
  backends; the =*ghostherd:= name is only the fallback -- and a buffer
  =ghostel-exec= runs a program in (eshell's visual commands): =ghostel=
  gives what it makes a =ghostel--buffer-identity=, =ghostel-exec= does
  not.
- A title never renames a dock terminal: its =ghostel--managed-buffer-name=
  is set to a non-name, which ghostel reads as "renamed by hand".

* The manager

=SPC b t= (and =t= in the =SPC b .= transient).  Posframe at the top of
the frame, clear of the panel, else a top side window.  This project's
terminals first, then each other project's, grouped (the project shows
on its first row), each group most recently used first.  Under a
project, dimmed, the terminals saved for it that are not open: those of
a project whose terminals have not come back this session (see "After
an Emacs restart").  A saved project whose directory is gone shows its
rows "missing".

| Key            | Action                                                       |
|----------------+--------------------------------------------------------------|
| =j= =k=        | Move (=C-n= =C-p=, =gg= =G=); the panel previews the row     |
| =RET=          | Open in the panel, selected; another project's terminal      |
|                | switches to its jworkspace layer first.  A saved one: bring  |
|                | it back, alone, then the same                                |
| =o=            | Open in the window the manager was opened from (a saved one: |
|                | brought back first)                                          |
| =n=            | New terminal in the selected row's project; asks its name    |
| =r=            | Rename (=*PROJECT:NAME*=); a saved one in the file           |
| =x=            | Kill; asks only when it runs something.  A saved one: drop   |
|                | it from the file, asked first                                |
| =K=            | Kill the selected row's project's idle ones; lists, asks     |
| =R=            | Rerun its last command (Up, Return) when idle; list stays.   |
|                | Not on a saved one: a fresh shell's Up is another history's  |
| =S=            | After a restart, start with its bound command, or no more;   |
|                | a saved one's flag, in the file                              |
| =F=            | Forget it: not back after a restart (again: keep it).  A     |
|                | saved one: out of the file, dimmed until the session ends    |
| =/=            | Filter: words matched in name, project, command, directory   |
| =g= (=gr=)     | Look again                                                   |
| =?=            | Key legend                                                   |
| =q= / Esc      | Close the help, clear the filter, else close; the panel goes |
|                | back as it was before the previews                           |

=x= is kill, not =k=: =k= moves, as in ghostherd's sidebar.  A shell
that gives OSC 133 is asked about by ghostel's own query
(=ghostel-query-before-killing=, which knows when a command runs); one
that does not, by the dock, from its foreground process.

Columns: project, name, what it runs now (=▶ npm run dev=, =idle=,
=exited=), the last command's exit status (=✓=, =✗ 2=, blank when the
shell never said), its directory (=./sub= under its root), how long
since its last output; =↻= after the name: it starts with its command
after a restart, a dim name: forgotten.  Under the list, the selected
one in full: its buffer and directory; what it runs, its last exit,
its last output; its last command line, its bound command, and whether
it comes back after a restart.  The rows are looked at again every
=ghostel-dock-refresh-interval= seconds while it shows.

The preview waits =ghostel-dock-preview-delay= (0.15 s) on a row: a
terminal shown resizes, and a full-screen program redraws.  A terminal
already in a window is not previewed.  Opening the manager selects the
project's most recent terminal that is not on screen, so =RET= goes
back to the one before.

* What a row knows, and how

- *What it runs*: the terminal's foreground process group, from
  =process-attributes= of =ghostel--pid= (the shell, or the =login(1)=
  that runs it on macOS: any process on the terminal reports the same
  =tpgid=).  When that group's leader is a shell (=ghostel-dock-shells=)
  it is idle; else its command line, the program's directory cut
  (=node /x/bin/npm run dev= shows =npm run dev=).  Two calls, about
  0.5 ms each on this machine.  Without a process: =OSC 133= running
  (=ghostel--command-running=) still shows =▶ running=.
- *Last exit status*: =ghostel-command-finish-functions= (OSC 133 D),
  counted only after a =ghostel-command-start-functions= (C): a prompt
  redrawn sends a D with the status of before.
- *Last output*: an =:after= advice on =ghostel--filter= and
  =ghostel--events-filter= -- the Emacs PTY's filter and the native
  PTY's event pipe, which gets an event (at least =()=) for every read.
- *Directory*: =default-directory=, which follows OSC 7.
- *Last command line*: while one runs, its foreground process's.  Else,
  from a shell giving OSC 133, the screen: ghostel's renderer marks the
  input at each prompt (=ghostel-input=), and the last command is the
  input at the prompt before the current one -- read only while the
  buffer is not waiting for a redraw.  Else the last one seen running
  (sampled 0.2 s after each OSC 133 C, and at every look).  Shown, never
  saved.

* Commands bound to a terminal (with ghostel-cmd)

A ghostel-cmd command can name its terminal: =:terminal "dev"= in its
record, set in the overlay's =a= / =e= flow; a discovered task's with
=e= on it, kept per project.  =T= runs any command in a terminal picked
on the spot.  Through =ghostel-dock-run=:

- The project's terminal of that name, started when missing (shown
  nowhere until then, so the shell is sized by the panel when it shows),
  shown in the panel and selected.
- A new shell gets the command once it shows its prompt: no job in the
  foreground and 0.4 s with no output (a login shell prints its rc
  files' output first), at most =ghostel-dock-ready-timeout= (15 s).
- Idle: it gets the command at once.
- Still running the same command a binding ran there: it is restarted.
  Ctrl-C (raw, so the tty raises SIGINT), then the command at the
  prompt: OSC 133 D when the shell gives it, else the foreground job
  gone.  A second Ctrl-C at half of =ghostel-dock-stop-timeout= (8 s);
  past it the command is not run and the echo area says so.  Nothing
  waits in the command loop: a 0.1 s timer looks, and a D looks at once.
- Running something else: asked first ("*web:dev* is running X; stop it
  and run Y?").
- RET pastes, C-RET runs, as for any command.  A command naming no
  terminal goes to the project's last-used one, as before.

"Still running the same": with OSC 133, from the binding's run until a
D ends it; without, until a look finds the terminal idle 1.5 s after
the run.  Without OSC 133 a command the user started by hand after
ours ended, before any look, would count as ours.

* After an Emacs restart

=ghostel-dock-save-file= (=emacs-home/ghostel-dock.eld=, git-ignored)
holds, per project root, its terminals the dock named, most recently
used first:

#+begin_src emacs-lisp
  ;; -*- mode: lisp-data -*-
  (:version 1 :terminals
   (("/Users/me/src/web/"
     (:name "shell" :dir "/Users/me/src/web/src/")
     (:name "dev" :dir "/Users/me/src/web/"
      :command "npm run dev" :start t))))
#+end_src

- Only name, directory, and the command a ghostel-cmd binding ran there
  with whether it starts with it.  No output, no history; the last
  command line of a row is never saved.
- Kept: terminals the dock named, not forgotten (=F=), in a local
  project.  One made before the dock is kept once =r= names it.  A
  shell that went remote (OSC 7 from an ssh) comes back in its root.
- Saved after a change -- made, renamed, killed, a bound command run, a
  flag set, a =cd= (seen at the next OSC 133 D) -- once Emacs has been
  idle a second, and at =kill-emacs=; written only when it changed.  A
  file that does not read is left alone and never written over.
- Back on the first =SPC '=, manager, =C-u SPC '= or bound command in a
  project after a restart: each shell started in its directory (its
  root when that is gone), shown nowhere, in saved order, so the one
  used last before is the last used again.  Only a terminal marked with
  =S= runs its command, once its prompt shows.
- A project not back yet keeps its saved terminals through every save
  this session: they are not gone, only not started.  The manager lists
  them under their project.
- =RET= on one of them brings back that terminal alone, in its
  directory, in its project's layer; marked =S=, it runs its command.
  Its project then counts as /picked/: its other saved terminals stay
  saved and listed, and no first =SPC '= there starts them behind your
  back -- you chose one by hand, so the rest wait for =RET= too.
  (Marking the project restored instead would drop the others from the
  file: phase 2 saves a restored project as it is open.)  Once open, the
  terminal's entry leaves the saved list: it is saved as it is now, and
  killed, it is gone.  A bound command for a saved terminal of a picked
  project brings that one back, as saved, and runs only the bound
  command.
- The manager's own project still comes back whole on its first
  =SPC b t=, as on =SPC '= and a bound run: the first touch of a project
  is one rule, whatever key it is.
- One that fails to start loses nothing: it stays saved and listed,
  and its project counts as picked.
- =x= kills it and it is gone from the file; =F= keeps it open but
  never brings it back.

* Shell integration (OSC 133 / OSC 7)

Measured 2026-11-06 in a scratch Emacs with the real ghostel: the
login shell here is =/bin/bash= (macOS's 3.2.57), and ghostel runs it
as =login -flp USER /bin/bash ... exec -l /bin/bash --posix= with
=ENV= pointing at its =inject.bash=.  bash 3.2 reads =ENV= only when it
runs as =sh=: with =--posix= it does not, login or not.  So nothing is
injected: no OSC 133, no OSC 7 (=default-directory= does not follow
=cd=), and the shell stays in POSIX mode, where bash 3.2 rejects
process substitution -- the fzf errors at each terminal's start.

The rows still work without it (what runs comes from the process
group); the exit status stays blank and the directory stays where the
terminal started.  What makes it work, in =~/.bashrc=, first:

#+begin_src sh
  if [[ "${INSIDE_EMACS%%,*}" = 'ghostel' && -n "$EMACS_GHOSTEL_PATH" ]]; then
      builtin unset ENV GHOSTEL_BASH_INJECT
      builtin source "$EMACS_GHOSTEL_PATH/etc/shell/ghostel.bash"
  fi
#+end_src

=ghostel.bash= leaves POSIX mode first thing and guards against a
second load.  Checked with that =.bashrc= under the same bash, the same
injection and a login shell: OSC 133 status and running, OSC 7 =cd=,
POSIX mode off.  (A newer bash, or zsh, as =ghostel-shell= would also
do: ghostel's zsh injection uses =ZDOTDIR=.)

* Layers

The panel is kept per window layer.  =ghostel-dock-without-panel= is an
=:around= advice for whatever snapshots a layer's windows or puts one
back; the config puts it on jworkspace's switch, maximize, delete and
save.  It hides the panel, remembering which terminal the layer showed
(per =ghostel-dock-layer-function=), runs the call, then shows the
panel the layer now current left -- selected again when the layer did
not change.  So a layer's saved layout never holds the panel.  Held, it
would come back as a side window without the =ghostel-dock= mark (Emacs
persists =window-side=, not the dock's parameter), showing whatever
buffer the snapshot named.  And jworkspace's maximize asks
=one-window-p=: with the panel up over a maximized window, the toggle
back would count the panel, maximize again and lose the layout it
saved.  (Unwrapped, maximizing also deletes the panel with the other
windows.)

=ghostel-dock-switch-layer-function= is called with a terminal's root
before the manager opens another project's terminal; the config's
switches to that project's jworkspace layer (asking before making one),
as =switch-terminal= did.

* For other code

- =(ghostel-dock-terminal &optional ROOT CREATE)= -- ROOT's last-used
  terminal (the current buffer's root by default); with CREATE, start
  one when there is none.
- =(ghostel-dock-show &optional BUFFER SELECT)= -- show it in the panel.
- =(ghostel-dock-rerun &optional BUFFER)= -- Up, Return, focus kept.
- =(ghostel-dock-terminals &optional ROOT)= -- ROOT's terminals, last
  used first; =t= for all.
- =(ghostel-dock-run COMMAND NAME &optional ROOT SUBMIT)= -- COMMAND in
  ROOT's terminal NAME, as above.
- =(ghostel-dock-terminal-names &optional ROOT)= -- ROOT's terminal
  names, open and saved.
- =ghostel-dock-after-create-functions= -- called with a new terminal
  and the buffer it was asked from (the config sends the python setup).

ghostel-cmd pastes into =ghostel-dock-terminal= of its overlay's root
when ghostel-dock is there (it asks =fboundp=), and shows it in the
panel; without it, as before.
