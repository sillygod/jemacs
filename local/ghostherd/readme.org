#+TITLE: ghostherd

Manage AI coding-agent CLIs inside [[https://github.com/dakra/ghostel][ghostel]] terminals — a herdr-inspired
control plane bound to the Emacs session.

* Status

| Item        | Value                                              |
|-------------+----------------------------------------------------|
| Phase       | *1 — MVP* (complete enough to dogfood)             |
| Lifetime    | Bound to Emacs (no background daemon / tmux yet)   |
| Branch      | developed on =chore/extract-personal-config=       |
| Package     | =local/ghostherd/= (straight =:local-repo=)        |
| Wired in    | =jemacs-ai= + leader =SPC a h=                     |

* Features (Phase 1)

- Spawn *claude* / *grok* / *agy* (or a plain shell) as named sessions
- Multiple concurrent agents per project (e.g. implementer + reviewer)
- Sidebar (=ghostherd-sidebar=) + consult switcher (=ghostherd-switch=)
- State polling: =working= / =blocked= / =idle= / =done= / =dead=
- Notifications via =alert= (config uses =osx-notifier=)
- Inter-agent messaging: =ghostherd-message=, =ghostherd-prompt=, =ghostherd-read=, =ghostherd-wait=
- Agents can call herd commands via =ghostel_cmd= (whitelisted)

** Sidebar keys

=?= help · =RET= visit · =e= explain · =N= new · =P= pair · =k= kill ·
=r= rename · =R= respawn · =c= note · =m= message · =i= prompt ·
=s= toggle project filter · =g= refresh · =.= next blocked ·
=M= mark state · =q= quit

=?= (=ghostherd-sidebar-help=) derives the listing from the buffer's live
keymaps rather than this table, so it stays correct under Evil or any
personal rebinding. Under =evil-collection= the sidebar inherits
=tabulated-list-mode='s *normal* state, where the single-letter keys above
are shadowed; a typical remap moves kill to =x= (so =k= still moves point)
and refresh to =gr= (so the =g= prefix survives). Press =?= to see what is
actually bound.

* Inter-agent communication

Herdr exposes pane/agent primitives over a socket. ghostherd mirrors the
useful subset in Elisp (and via =ghostel_cmd= from inside an agent shell).

** Elisp

#+begin_src emacs-lisp
  ;; Submit work to the reviewer and wait until settled
  (ghostherd-prompt "reviewer" "Review the current diff for security issues" t 180)

  ;; Message with attribution (from implementer → reviewer)
  (ghostherd-message "implementer" "reviewer"
                     "Please review commits on this branch."
                     :submit t)

  ;; Read another agent's recent screen
  (ghostherd-read "reviewer" 80)

  ;; Wait for blocked/idle/done
  (ghostherd-wait "reviewer" '(blocked idle done) 120)
#+end_src

** From an agent shell (ghostel_cmd)

When shell integration is active and the command is whitelisted:

#+begin_src bash
  ghostel_cmd ghostherd-list
  ghostel_cmd ghostherd-state reviewer
  ghostel_cmd ghostherd-prompt reviewer "Review the diff"
  ghostel_cmd ghostherd-message reviewer "Please review" implementer
  ghostel_cmd ghostherd-read reviewer 60
#+end_src

Typical workflow:
1. =SPC a h 2= → implementer (claude) | reviewer (claude or grok)
2. Work in implementer
3. =SPC a h m= → message reviewer with a review request
4. =SPC a h .= when reviewer is blocked / done

* Notifications (ghostel hooks)

ghostherd reuses ghostel's process lifecycle rather than inventing a
parallel notifier:

| Signal                       | Source                        | Herd action            |
|------------------------------+-------------------------------+------------------------|
| Process exit                 | =ghostel-exit-functions=      | state → =dead=, notify |
| OSC 133 command start/finish | =ghostel-command-*-functions= | shell kind state hints |
| OSC 9;4 progress             | =ghostel-progress-function=   | → =working= (+ %)      |
| OSC 2 title                  | =ghostel--title=              | sidebar Title column   |
| Screen rules (poll)          | timer                         | working/blocked/idle   |
| Desktop notify               | =alert= / =osx-notifier=      | blocked / done / dead  |

Two notes on the OSC integrations, because neither is a hook:

- =ghostel-progress-function= is a single global function, very likely
  someone's spinner. ghostherd saves and *chains to* the previous value, and
  restores it when =ghostherd-mode= is disabled. Its handler runs
  synchronously on ghostel's VT-parser callpath, where slow work stalls
  terminal output, so it only records the report; the poll path decides what
  it means.
- The title is read straight off buffer-local =ghostel--title=. Going through
  =ghostel-buffer-name-function= (ghostel's title→buffer-name mapping) would
  fight ghostherd's own buffer naming.

* Why is it in that state? (=ghostherd-explain=)

=e= in the sidebar, or =M-x ghostherd-explain=. Shows the scraped tail, every
=:screen-rules= pattern that matched it, and which one won:

#+begin_example
  agy-review  (agy)

    state    ○ idle
    reason   —
    buffer   *ghostherd:agy-review*

  Matches, in precedence order (blocked > working > idle):

    blocked  ->  Do you want to proceed
    working      Running
    working      esc to interrupt
    idle         ^>

  Only the first line wins.  A rule listed under a
  higher-precedence state shadows every rule below it.
#+end_example

Rule tuning is guesswork without this. A false =blocked= looks exactly like a
real one until you can see *which* pattern matched, and that the agent had
merely printed the words rather than stopped on a prompt.

** Detection notes per CLI

Screen rules are heuristics against a UI that changes between releases, so
record what was observed against which version. Prefer a *missed* =blocked=
over a false one.

| CLI    | Version tested | Known false positive / miss | Fix applied |
|--------+----------------+-----------------------------+-------------|
| claude |                |                             |             |
| grok   |                |                             |             |
| agy    | 1.1.12         |                             |             |

Agent buffers set =ghostel-kill-buffer-on-exit= to nil so an exited
session stays visible as =dead= until you kill it from the herd.

* Config knobs

#+begin_src emacs-lisp
  (setq ghostherd-default-kind 'claude
        ghostherd-poll-interval 1.5
        ghostherd-spawn-delay 0.8
        ghostherd-notify-on-blocked t
        ghostherd-sidebar-side 'left)

  ;; OSC 9;4 progress as evidence of `working'
  (setq ghostherd-use-osc-progress t
        ghostherd-progress-ttl 5)         ; seconds a report stays trusted

  ;; OSC 2 title as a sidebar column.  Columns are fitted to the sidebar
  ;; width, and Title outranks Project, so in a narrow sidebar this trades
  ;; the project path for the title rather than overflowing.
  (setq ghostherd-sidebar-show-title nil)

  ;; Permanent default args example:
  (setf (alist-get 'claude ghostherd-agent-specs)
        (plist-put (alist-get 'claude ghostherd-agent-specs)
                   :args '("--permission-mode" "acceptEdits")))
#+end_src

* Testing

** Automated (=ghostherd-tests.el=)

#+begin_src bash
  cd local/ghostherd
  emacs --batch -L . -l ghostherd.el -l ghostherd-tests.el \
        -f ert-run-tests-batch-and-exit
#+end_src

Covers the parts that need no PTY: rule matching and precedence, OSC
progress freshness and handler chaining, state-detection precedence, sidebar
column fitting, title filtering, naming and age formatting.

The suite was mutation-checked rather than merely run --- breaking the
blocked-beats-progress rule, the progress chaining, the column budget, the
mandatory-column flag and the title filter each fail a test. That exercise
found a real defect: a floor on the column budget made the mandatory flag
unreachable, so it was dead code (and the floor caused overflow at very
narrow widths).

** Manual

The interactive spawn/kill paths still need a human, since driving real
ghostel PTYs headlessly is what Phase 1 deferred. Run after reloading config
(or restarting Emacs) so =local/ghostherd= and leader keys are loaded.

** Prerequisites

1. =ghostel= package installed and working (=M-x ghostel= opens a shell).
2. CLIs on =PATH=: =claude=, =grok=, =agy= (skip kinds you do not have).
3. =alert= available (this config sets =alert-default-style= to =osx-notifier=).
4. =jemacs-ai= loaded so =use-package ghostherd= ran; first command will load the package and enable =ghostherd-mode=.

** Smoke (load / compile)

In a shell:

#+begin_src bash
  emacs --batch \
    --eval "(add-to-list 'load-path \"~/.emacs.d/local/ghostherd\")" \
    --eval "(byte-compile-file \"~/.emacs.d/local/ghostherd/ghostherd.el\")"
#+end_src

Expect: no errors (warnings about free vars from ghostel internals are OK if any).

In Emacs:

#+begin_src emacs-lisp
  (require 'ghostherd)
  (ghostherd-mode 1)
  (featurep 'ghostherd)   ; => t
#+end_src

* Roadmap (remaining phases)

Phase 1 (this tree) is intentionally small: spawn, list, switch, state,
notify, pair layout, message/prompt/read/wait.

** Phase 1.1 — Stabilize detection (next dogfood pass)

Goal: make state trustworthy for daily use without false blocked spam.

- [X] =ghostherd-explain= (like herdr =agent explain=): show last tail
  snippet + which rule matched
- [X] OSC progress (=ghostel-progress-function=) → force =working= + %
- [X] OSC title → sidebar summary column (opt-in; see the width note under
  Config knobs)
- [ ] Tune =:screen-rules= per CLI after T4 sessions — needs real dogfood
  data; =ghostherd-explain= is what produces it
- [ ] Document known false positives per agent version — table stubbed under
  "Detection notes per CLI"

- [X] Sidebar columns are fitted to the window instead of overflowing it.
  They used to be a fixed vector needing ~70 characters against a default
  width of 36, so every row wrapped. =ghostherd--sidebar-column-specs= now
  lists candidates most-useful-first and the widest, least informative ones
  (=Project=, then =Kind=) drop out when there is no room. The fit follows a
  manual resize, not just =ghostherd-sidebar-width=.

** Phase 2 — Usability

Goal: less friction for multi-agent day-to-day work.

- [ ] Layout presets beyond pair (e.g. 1+2 grid, focus agent only)
- [X] Session notes editable from sidebar (=c=); role shown in switcher
- [ ] Persist last herd snapshot for the Emacs session restart *within*
  one day (desktop.el / custom file) — still bound to Emacs, not detach
- [ ] Per-project default kinds/args via dir-locals
- [X] Consult annotations (kind, project, age, notes) --- candidates are
  now bare names with the detail in an affixation, so typing matches the
  name instead of whatever happened to be concatenated into the string
- [X] ERT unit tests for pure helpers (rules, naming, format) ---
  =ghostherd-tests.el=, mutation-checked

- [X] =ghostherd-respawn= (=R= in the sidebar) --- was two roadmap items,
  "persist snapshot" and "restart-agent", which turned out to be the same
  thing

** What a snapshot can and cannot hold

Agents are Emacs child processes: when Emacs exits, they exit. So the most
that can be persisted is the *recipe* --- kind, directory, args, notes ---
which is exactly what =ghostherd-session-recipe= returns.

The conversation is not in the recipe, and never can be. But it is not lost
either: it lives in the CLI's own store, and each CLI has a flag to reopen
it. That flag is declared per kind as =:continue-args= in
=ghostherd-agent-specs= rather than hardcoded, so a CLI without one is
representable (=shell= has none) and respawn refuses instead of silently
starting cold.

=ghostherd-respawn= therefore gets most of the way to "my herd came back"
with no new dependency: it frees the old buffer and id, then respawns from
the recipe, appending =:continue-args= when asked. Note *appending* --- a
session spawned with =--model= must come back on that model, not the
default.

Surviving an Emacs quit for real is Phase 3, and needs a process that is not
an Emacs child.

** Phase 2.5 — Richer automation (herdr-like control)

Goal: scripts and agents can orchestrate without focusing panes.

- [ ] =ghostherd-wait-output= (regex on buffer tail, timeout)
- [ ] =ghostherd-send-keys= (esc, ctrl+c, etc. via =ghostel-send-key=)
- [ ] Pipeline helper: implement → message reviewer → wait → notify
- [ ] Structured JSON-ish listing for =ghostherd-cmd-list=
- [ ] Optional =emacsclient= CLI wrapper script
  (=bin/ghostherd= → =emacsclient -e '(ghostherd-…)'=)

** Phase 3 — Detach / survive Emacs quit

Goal: optional herdr-like lifetime (agents keep running if Emacs dies).

- [ ] Backend abstraction: =ghostel= (current) \| =tmux= \| =dtach=
- [ ] Attach/detach UI still through ghostel (tmux attach in buffer)
- [ ] Restore herd registry from backend session list on Emacs start
- [ ] Explicit non-goal until then: phone SSH thin client, full socket
  server compatible with herdr

** Phase 4 — Ecosystem (only if still useful)

- [ ] Extract =ghostherd= to its own repo / MELPA if others want it
- [ ] Optional lifecycle hooks plugins per CLI (beyond screen scrape)
- [ ] Compare/contrast doc vs herdr for users choosing tools

** Explicit non-goals (for now)

- Replacing gptel / copilot / in-buffer LLM workflows
- Implementing a full A2A network protocol
- Windows-first support (macOS/Linux Emacs + ghostel is the target)

* Architecture sketch

#+begin_src text
  UI: sidebar | consult | modeline | alert
           │
  Control: spawn kill rename prompt message wait
           │
  Detect:  timer + screen rules + ghostel-exit / OSC hooks
           │
  Runtime: ghostel buffers (real PTYs), one per session
#+end_src

Sessions live in =ghostherd--sessions= (id → =ghostherd-session= struct).
Buffer-local =ghostherd-session-id= links the PTY buffer back to the registry.

* Design decisions log

| Decision              | Choice                                      | Why                                      |
|-----------------------+---------------------------------------------+------------------------------------------|
| Lifetime              | Bound to Emacs first                        | Simpler; detach is Phase 3               |
| UI                    | Sidebar *and* consult                       | Herd overview + fast jump                |
| Agents                | claude, grok, agy (+ shell)                 | What this machine runs                   |
| Multi-agent           | First-class (pair + message)                | Review / implement split is common       |
| Spawn strategy        | Shell then send CLI line                    | Matches “terminal owns agent”; flexible  |
| State authority       | Screen rules + exit hooks                   | No per-CLI lifecycle plugins yet         |
| Blocked policy        | Strict (miss rather than false positive)    | Same as herdr                            |
| Notify                | Reuse ghostel hooks + alert                 | No parallel notifier                     |
| Kill-on-exit          | Off for herd buffers                        | Keep =dead= rows visible                 |
