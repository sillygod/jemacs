#+TITLE: ghostherd

Manage AI coding-agent CLIs inside [[https://github.com/dakra/ghostel][ghostel]] terminals — a herdr-inspired
control plane bound to the Emacs session.

* Features (Phase 1)

- Spawn *claude* / *grok* / *agy* (or a plain shell) as named sessions
- Multiple concurrent agents per project (e.g. implementer + reviewer)
- Sidebar (=ghostherd-sidebar=) + consult switcher (=ghostherd-switch=)
- State polling: =working= / =blocked= / =idle= / =done= / =dead=
- Notifications via =alert= (config uses =osx-notifier=)
- Inter-agent messaging: =ghostherd-message=, =ghostherd-prompt=, =ghostherd-read=, =ghostherd-wait=
- Agents can call herd commands via =ghostel_cmd= (whitelisted)

=?= (=ghostherd-sidebar-help=) derives the listing from the buffer's live
keymaps rather than this table, so it stays correct under Evil or any
personal rebinding. Under =evil-collection= the sidebar inherits
=tabulated-list-mode='s *normal* state, where the single-letter keys above
are shadowed; a typical remap moves kill to =x= (so =k= still moves point)
and refresh to =gr= (so the =g= prefix survives). Press =?= to see what is
actually bound.

* Inter-agent communication

Herdr exposes pane/agent primitives over a socket. ghostherd mirrors the
useful subset in Elisp (and via =ghostel_cmd= from inside an agent shell).

** Elisp

#+begin_src emacs-lisp
  ;; Submit work to the reviewer and wait until settled
  (ghostherd-prompt "reviewer" "Review the current diff for security issues" t 180)

  ;; Message with attribution (from implementer → reviewer)
  (ghostherd-message "implementer" "reviewer"
                     "Please review commits on this branch."
                     :submit t)

  ;; Read another agent's recent screen
  (ghostherd-read "reviewer" 80)

  ;; Wait for blocked/idle/done
  (ghostherd-wait "reviewer" '(blocked idle done) 120)
#+end_src

** From an agent shell (ghostel_cmd)

When shell integration is active and the command is whitelisted:

#+begin_src bash
  ghostel_cmd ghostherd-list
  ghostel_cmd ghostherd-state reviewer
  ghostel_cmd ghostherd-prompt reviewer "Review the diff"
  ghostel_cmd ghostherd-message reviewer "Please review" implementer
  ghostel_cmd ghostherd-read reviewer 60
#+end_src

=ghostherd-list= and =ghostherd-state= emit JSON:

#+begin_example
  [{"name":"reviewer","kind":"grok","state":"blocked","reason":"Approve",
    "project":"/src/app/","notes":"reviews auth","age":"3m"}]
#+end_example

Not for tidiness --- the previous tab/equals format had no escaping, and two
of the fields are free text. A note containing a tab or newline turned one
record into several, and =reason= holds a raw =:screen-rules= regexp, which
can contain anything. An unknown session reports ={"error":...}= rather than
a prose string, so a caller can tell a failure from a session that happens
to be named like one.

Typical workflow:
1. =SPC a h 2= → implementer (claude) | reviewer (claude or grok)
2. Work in implementer
3. =SPC a h m= → message reviewer with a review request
4. =SPC a h .= when reviewer is blocked / done

* Talking to an agent vs operating it

Two different things, and only the first existed before Phase 2.5.

=ghostherd-send= / =ghostherd-prompt= paste *text* and optionally press
Return. That is how you talk *to* an agent, and it assumes the agent is
sitting there waiting for input.

=ghostherd-send-keys= sends *keystrokes*. Escaping a runaway generation,
answering an arrow-driven permission menu, sending EOF --- none of these are
text. Pasting the characters =esc= just feeds the agent a word.

#+begin_src emacs-lisp
  (ghostherd-interrupt "reviewer")          ; Escape -- "esc to interrupt"
  (ghostherd-abort "reviewer")              ; C-c
  (ghostherd-answer "reviewer" 2)           ; pick option 2 of a menu
  (ghostherd-send-keys "reviewer" "tab" "down" "return")
#+end_src

Three things worth knowing:

- Keys do *not* mark the session =working=, though text input does. The usual
  reason to send a key is to make the agent *stop*; claiming it just started
  would be backwards. The next poll reports what actually happened.
- =ghostherd-answer= presses Up several times before descending. The
  highlighted option is not necessarily the first, and counting down from
  wherever the cursor happens to be picks the wrong answer. Some CLIs accept
  the digit as text and some only respond to arrows; there is no way to tell
  from outside, and arrows work for both.
- Friendly names (=esc=, =C-c=, =down=) are mapped in
  =ghostherd-key-aliases=. Anything unlisted is passed through to
  =ghostel-send-key= unchanged, so its full vocabulary stays reachable.

* Waiting

=ghostherd-wait= watches the state machine, which only knows the five states
the screen rules can produce. Plenty of things worth waiting for have no
state of their own --- a test summary, a specific error, the agent naming
the file it just wrote.

#+begin_src emacs-lisp
  (ghostherd-wait "reviewer" '(blocked idle done) 120)   ; by state
  (ghostherd-wait-output "reviewer" "[0-9]+ failures" 300)  ; by output
  (ghostherd-wait-output "reviewer" "deployed" 60 t)     ; nil instead of error
#+end_src

- Returns the matched text; signals on timeout unless NOERROR, because
  scripts branching on "did it happen" should not have to wrap every call in
  =condition-case=.
- Checks *before* sleeping. Output can arrive between whatever triggered the
  wait and the wait itself, and a first check one interval late would miss
  it.
- Gives up when the session dies. A dead agent will never produce the text;
  waiting out the full timeout for it is just a hang.
- Matching is *case-sensitive*, unlike =:screen-rules= --- see below.

** Known issue: rule matching case

=:screen-rules= use =string-match-p= under whatever =case-fold-search=
happens to be at poll time, which is not something the rule author controls.
=ghostherd-output-matches= binds it to nil deliberately so a regexp means
what it says. The rules should probably do the same, but changing it would
silently alter what every existing pattern matches, so it wants a dogfood
pass rather than a quiet fix.

* Handing work to another agent

=ghostherd-handoff= is the pipeline primitive: message an agent, watch it,
report.

#+begin_src emacs-lisp
  ;; from the implementer, hand a review request to the reviewer
  (ghostherd-handoff "reviewer" "Review the diff on this branch"
                     "implementer")

  ;; with your own completion handler
  (ghostherd-handoff "reviewer" "Run the suite" "user" 300
                     (lambda (session state)
                       (when (eq state 'done)
                         (pop-to-buffer (ghostherd-session-buffer session)))))
#+end_src

*It is asynchronous, deliberately.* =ghostherd-wait= blocks in a =sit-for=
loop, which would freeze you out of the very editor you are meant to keep
working in while the other agent runs --- and orchestrating without sitting
and watching a pane is the entire point of this phase. There is a test that
fails if a handoff ever calls =sit-for=.

Two things it has to get right:

- *Grace window.* An agent does not start the instant it is handed
  something: the CLI has to wake up and print, and until it does the screen
  rules still see the idle prompt from before. Without
  =ghostherd-handoff-grace= the watch would report completion immediately,
  every time.
- *One watch per agent.* Handing off to an agent that is already being
  watched replaces the watch instead of stacking a second timer on it, and a
  callback that throws cancels the watch rather than leaving it polling
  forever.

* From a shell (=bin/ghostherd=)

=ghostel_cmd= reaches the herd from inside an agent's own terminal. This is
for everywhere else --- a Makefile, a git hook, a CI step:

#+begin_src bash
  bin/ghostherd list                       # JSON
  bin/ghostherd state reviewer
  bin/ghostherd prompt reviewer "Run the suite"
  bin/ghostherd handoff reviewer "Review the diff" implementer
  bin/ghostherd keys reviewer down down return
  bin/ghostherd interrupt reviewer
#+end_src

=GHOSTHERD_SOCKET= picks an emacsclient socket; =GHOSTHERD_DRY_RUN= prints
the elisp instead of running it, which is how the quoting is tested.

Two things it has to get right, both learned the hard way:

- *Quoting.* Every argument is free text --- a prompt can contain quotes,
  backslashes and newlines --- so it is escaped into an Emacs Lisp string
  literal rather than interpolated. Verified by round-tripping through the
  Emacs reader, not by eyeballing.
- *Output goes through a temp file, and the write is pinned to UTF-8.*
  =emacsclient -e= prints the *Lisp representation*, so JSON would come back
  double-escaped as ="[{\"name\":...}]"=. Writing to a file avoids that ---
  but agent output is full of non-ASCII (box drawing, the =❯= in a
  permission prompt), and =write-region= without an explicit coding system
  calls =select-safe-coding-system=, which *prompts*. In batch that is an
  error; in a daemon it blocks forever on a minibuffer nobody can answer and
  wedges the server for every later call too. That is not hypothetical: it
  is what the first version did.

* Notifications (ghostel hooks)

ghostherd reuses ghostel's process lifecycle rather than inventing a
parallel notifier:

| Signal                       | Source                        | Herd action            |
|------------------------------+-------------------------------+------------------------|
| Process exit                 | =ghostel-exit-functions=      | state → =dead=, notify |
| OSC 133 command start/finish | =ghostel-command-*-functions= | shell kind state hints |
| OSC 9;4 progress             | =ghostel-progress-function=   | → =working= (+ %)      |
| OSC 2 title                  | =ghostel--title=              | sidebar Title column   |
| Screen rules (poll)          | timer                         | working/blocked/idle   |
| Desktop notify               | =alert= / =osx-notifier=      | blocked / done / dead  |

Two notes on the OSC integrations, because neither is a hook:

- =ghostel-progress-function= is a single global function, very likely
  someone's spinner. ghostherd saves and *chains to* the previous value, and
  restores it when =ghostherd-mode= is disabled. Its handler runs
  synchronously on ghostel's VT-parser callpath, where slow work stalls
  terminal output, so it only records the report; the poll path decides what
  it means.
- The title is read straight off buffer-local =ghostel--title=. Going through
  =ghostel-buffer-name-function= (ghostel's title→buffer-name mapping) would
  fight ghostherd's own buffer naming.

* Why is it in that state? (=ghostherd-explain=)

=e= in the sidebar, or =M-x ghostherd-explain=. Shows the scraped tail, every
=:screen-rules= pattern that matched it, and which one won:

#+begin_example
  agy-review  (agy)

    state    ○ idle
    reason   —
    buffer   *ghostherd:agy-review*

  Matches, in precedence order (blocked > working > idle):

    blocked  ->  Do you want to proceed
    working      Running
    working      esc to interrupt
    idle         ^>

  Only the first line wins.  A rule listed under a
  higher-precedence state shadows every rule below it.
#+end_example

Rule tuning is guesswork without this. A false =blocked= looks exactly like a
real one until you can see *which* pattern matched, and that the agent had
merely printed the words rather than stopped on a prompt.

** Detection notes per CLI

Screen rules are heuristics against a UI that changes between releases, so
record what was observed against which version. Prefer a *missed* =blocked=
over a false one.

| CLI    | Version tested | Known false positive / miss | Fix applied |
|--------+----------------+-----------------------------+-------------|
| claude |                |                             |             |
| grok   |                |                             |             |
| agy    | 1.1.12         |                             |             |

Agent buffers set =ghostel-kill-buffer-on-exit= to nil so an exited
session stays visible as =dead= until you kill it from the herd.

* Per-project defaults

Drop this in a project's =.dir-locals.el= and =ghostherd-new= preselects the
kind and prefills the args:

#+begin_src emacs-lisp
  ((nil . ((ghostherd-project-kind . claude)
           (ghostherd-project-args . ("--permission-mode" "acceptEdits")))))
#+end_src

Both are marked =safe-local-variable= for their expected shapes, so no
prompt. They are read *by directory* rather than from the current buffer:
=ghostherd-new= is often invoked from the sidebar or another non-file buffer,
which never picked up the project's dir-locals at all.

Resolved before the kind prompt so the project can preselect it. Changing
the directory later in the same prompt sequence does not re-read --
re-prompting for a kind you already answered would be worse than stale.

* Config knobs

#+begin_src emacs-lisp
  (setq ghostherd-default-kind 'claude
        ghostherd-poll-interval 1.5
        ghostherd-spawn-delay 0.8
        ghostherd-notify-on-blocked t
        ghostherd-sidebar-side 'left)

  ;; OSC 9;4 progress as evidence of `working'
  (setq ghostherd-use-osc-progress t
        ghostherd-progress-ttl 5)         ; seconds a report stays trusted

  ;; OSC 2 title as a sidebar column.  Columns are fitted to the sidebar
  ;; width, and Title outranks Project, so in a narrow sidebar this trades
  ;; the project path for the title rather than overflowing.
  (setq ghostherd-sidebar-show-title nil)

  ;; Permanent default args example:
  (setf (alist-get 'claude ghostherd-agent-specs)
        (plist-put (alist-get 'claude ghostherd-agent-specs)
                   :args '("--permission-mode" "acceptEdits")))
#+end_src

* Testing

** Automated (=ghostherd-tests.el=)

#+begin_src bash
  cd local/ghostherd
  emacs --batch -L . -l ghostherd.el -l ghostherd-tests.el \
        -f ert-run-tests-batch-and-exit
#+end_src

Covers the parts that need no PTY: rule matching and precedence, OSC
progress freshness and handler chaining, state-detection precedence, sidebar
column fitting, title filtering, naming and age formatting.

The suite was mutation-checked rather than merely run --- breaking the
blocked-beats-progress rule, the progress chaining, the column budget, the
mandatory-column flag and the title filter each fail a test. That exercise
found a real defect: a floor on the column budget made the mandatory flag
unreachable, so it was dead code (and the floor caused overflow at very
narrow widths).

** Manual

The interactive spawn/kill paths still need a human, since driving real
ghostel PTYs headlessly is what Phase 1 deferred. Run after reloading config
(or restarting Emacs) so =local/ghostherd= and leader keys are loaded.

** Prerequisites

1. =ghostel= package installed and working (=M-x ghostel= opens a shell).
2. CLIs on =PATH=: =claude=, =grok=, =agy= (skip kinds you do not have).
3. =alert= available (this config sets =alert-default-style= to =osx-notifier=).
4. =jemacs-ai= loaded so =use-package ghostherd= ran; first command will load the package and enable =ghostherd-mode=.

** Smoke (load / compile)

In a shell:

#+begin_src bash
  emacs --batch \
    --eval "(add-to-list 'load-path \"~/.emacs.d/local/ghostherd\")" \
    --eval "(byte-compile-file \"~/.emacs.d/local/ghostherd/ghostherd.el\")"
#+end_src

Expect: no errors (warnings about free vars from ghostel internals are OK if any).

In Emacs:

#+begin_src emacs-lisp
  (require 'ghostherd)
  (ghostherd-mode 1)
  (featurep 'ghostherd)   ; => t
#+end_src

* Roadmap (remaining phases)

Phase 1 (this tree) is intentionally small: spawn, list, switch, state,
notify, pair layout, message/prompt/read/wait.

** Phase 1.1 — Stabilize detection (next dogfood pass)

Goal: make state trustworthy for daily use without false blocked spam.

- [X] =ghostherd-explain= (like herdr =agent explain=): show last tail
  snippet + which rule matched
- [X] OSC progress (=ghostel-progress-function=) → force =working= + %
- [X] OSC title → sidebar summary column (opt-in; see the width note under
  Config knobs)
- [ ] Tune =:screen-rules= per CLI after T4 sessions — needs real dogfood
  data; =ghostherd-explain= is what produces it
- [ ] Document known false positives per agent version — table stubbed under
  "Detection notes per CLI"

- [X] Sidebar columns are fitted to the window instead of overflowing it.
  They used to be a fixed vector needing ~70 characters against a default
  width of 36, so every row wrapped. =ghostherd--sidebar-column-specs= now
  lists candidates most-useful-first and the widest, least informative ones
  (=Project=, then =Kind=) drop out when there is no room. The fit follows a
  manual resize, not just =ghostherd-sidebar-width=.

** Phase 2 — Usability

Goal: less friction for multi-agent day-to-day work.

- [-] Layout presets beyond pair (1+2 grid, focus agent only) --- *decided
  against*. =ghostherd-new-pair= covers the split that actually gets used,
  and window layout is something Emacs already has better tools for than a
  herd manager should reimplement.
- [X] Session notes editable from sidebar (=c=); role shown in switcher
- [X] Per-project default kinds/args via dir-locals
- [X] Consult annotations (kind, project, age, notes) --- candidates are
  now bare names with the detail in an affixation, so typing matches the
  name instead of whatever happened to be concatenated into the string
- [X] ERT unit tests for pure helpers (rules, naming, format) ---
  =ghostherd-tests.el=, mutation-checked

- [X] =ghostherd-respawn= (=R= in the sidebar) --- was two roadmap items,
  "persist snapshot" and "restart-agent", which turned out to be the same
  thing

** What a snapshot can and cannot hold

Agents are Emacs child processes: when Emacs exits, they exit. So the most
that can be persisted is the *recipe* --- kind, directory, args, notes ---
which is exactly what =ghostherd-session-recipe= returns.

The conversation is not in the recipe, and never can be. But it is not lost
either: it lives in the CLI's own store, and each CLI has a flag to reopen
it. That flag is declared per kind as =:continue-args= in
=ghostherd-agent-specs= rather than hardcoded, so a CLI without one is
representable (=shell= has none) and respawn refuses instead of silently
starting cold.

=ghostherd-respawn= therefore gets most of the way to "my herd came back"
with no new dependency: it frees the old buffer and id, then respawns from
the recipe, appending =:continue-args= when asked. Note *appending* --- a
session spawned with =--model= must come back on that model, not the
default.

Surviving an Emacs quit for real is Phase 3, and needs a process that is not
an Emacs child.

** Phase 2.5 — Richer automation (herdr-like control)

Goal: scripts and agents can orchestrate without focusing panes.

- [X] =ghostherd-wait-output= (regex on buffer tail, timeout)
- [X] =ghostherd-send-keys= (esc, ctrl+c, arrows, tab) --- plus
  =ghostherd-interrupt= / =ghostherd-abort= / =ghostherd-answer=
- [X] Pipeline helper: implement → message reviewer → wait → notify
  (=ghostherd-handoff=)
- [X] Structured JSON listing for =ghostherd-cmd-list= / =ghostherd-cmd-state=
- [X] =emacsclient= CLI wrapper (=bin/ghostherd=)

** Phase 3 — tmux as a headless PTY host

Goal: read the agent's screen out of band, and let sessions outlive Emacs.

Originally written as "detach / survive Emacs quit", which undersold it.
Survival is the *smaller* prize. The larger one is =tmux capture-pane=:
state detection today scrapes the Emacs buffer, which is why so much of
Phase 1.1 went into fighting alt-screen behaviour, resize repaints and
what ghostel had or had not rendered yet. capture-pane reads the pane
directly, works when nothing is attached, and does not care how ghostel
draws. =send-keys= likewise injects input without needing focus.

tmux is here as a *named, detachable PTY that can dump its own screen*,
not as a second multiplexer. Emacs already multiplexes; herdr *is* a
multiplexer. Putting tmux windows or panes in the middle would be a
third navigation layer inside ghostel (prefix keys, attach-the-whole-
session, layout fighting Emacs). That mapping is rejected.

*** Mapping

One ghostherd session = one tmux session, on a dedicated socket.

#+begin_src text
  tmux -L ghostherd
    session gh-<project>-<name>     implementer  (one window, one pane)
    session gh-<project>-<name>     reviewer
    session gh-<project>-<name>     explorer
#+end_src

Each tmux session contains only the default window and pane. Those are
implementation details; they do not appear in ghostherd's data model.
=status off= and =prefix None= so an attached client looks like a raw
PTY, not like tmux. The user's own =tmux= (default socket) is
untouched.

Not a window in a shared herd session --- that makes tmux's window
switcher a second =ghostherd-switch=, and killing the session kills
everyone. Not a pane in a tiled window --- that is herdr's model, and
it fights Emacs window layout the same way Phase 2 already declined to.

Naming: tmux targets treat =:= and =.= as punctuation
(=session:window.pane=), so ids look like =gh-<project-hash>-<name>=
rather than =ghostherd:reviewer=. =tmux -L ghostherd list-sessions= is
then the registry to restore on Emacs start.

*** Attach is optional

Nobody needs to be attached for the herd to work. Detection reads
=capture-pane=; input goes through =send-keys=. Visiting an agent
(=RET= in the sidebar, =ghostherd-switch=) is the only time ghostel
runs =tmux attach -t …=. Closing the buffer detaches; the process
stays. That is the herdr sentence this phase is actually after:
nobody is attached to any of it right now.

*** Work items

See the implementation plan below. Short version:

- [ ] Backend as capabilities, not product names: =capture=,
  =send-text=, =send-keys=, =spawn= / =kill= / =list= / =live-p=
- [ ] Current ghostel path extracted behind that slot (no behaviour
  change). tmux implements all four host jobs. dtach is *not* a
  substitute --- no capture, so it misses the larger prize
- [ ] Dedicated socket + one tmux session per agent; status off,
  prefix off; ghostel only attaches when the user visits
- [ ] Restore the herd registry from =tmux -L ghostherd list-sessions=
  plus recipe options stashed on the session
- [ ] Explicit non-goal until then: phone SSH thin client, full socket
  server compatible with herdr

A later split is still available if capture-from-ghostel (a real VT
grid API, not the buffer text) lands first. That would be the larger
prize without the nested VT. Persistence can then be a thinner host.
Until that exists, tmux is the one widely-installed tool that does
both jobs.

*** What it costs

Two terminal emulators nested: tmux's VT inside ghostel's, but only
for the agent you are looking at. Phase 1.1 already spent real effort
on one layer of SIGWINCH and repaint behaviour (see the resize
debounce in =jemacs-project.el=); attach adds another. Prefix collision
is avoided by turning the prefix off. Alt-screen still passes through
one more translation on the attach path; the detect path does not
care, because it never goes through ghostel.

*** When to pull it forward

**If tuning =:screen-rules= turns out to be painful, that is the signal.**
The tuning loop is only hard because the thing being scraped is a rendering
of a rendering. capture-pane removes that indirection, so a Phase 1.1 that
keeps fighting the buffer is really a Phase 3 argument in disguise.

*** Implementation plan

Written so the next person can implement without this conversation.
Default backend stays =ghostel= until the tmux path is dogfooded; this
phase is additive.

**** What is coupled today

Every I/O path assumes a live ghostel buffer. Those are the call
sites that have to go through the backend slot:

| Job | Today | After |
|-----+-------+-------|
| Screen text | =ghostherd--buffer-tail= | =ghostherd-backend-capture= |
| Type text | =ghostel-paste-string= in =ghostherd-send= | =ghostherd-backend-send-text= |
| Type keys | =ghostel-send-key= in =ghostherd-send-keys= | =ghostherd-backend-send-keys= |
| Alive? | =ghostherd--session-live-p= = buffer-live-p | host process, not the view |
| Spawn | =ghostel= then send the CLI line | host creates the PTY |
| Die | =ghostel-exit-functions= → state =dead= | *only* when the host process dies |
| Read / explain / wait-output | buffer tail | capture |
| Title | buffer-local =ghostel--title= | =#{pane_title}= when detached |

Public commands (=ghostherd-prompt=, =ghostherd-message=,
=ghostherd-handoff=, =ghostherd-interrupt=, …) stay as they are.
They already go through send / send-keys / read / wait.

**** Backend slot

Capabilities, not product names. =cl-defgeneric= is fine --- the
file already uses =cl-lib=. Two implementors: =ghostel= (extract
what exists) and =tmux=. Do not add a dtach implementor; it cannot
satisfy =capture=.

Suggested names, all taking a =ghostherd-session= except =list= /
=spawn=:

- =ghostherd-backend-capture (session &optional n)= → string
- =ghostherd-backend-send-text (session text submit)=
- =ghostherd-backend-send-keys (session keys)=
- =ghostherd-backend-live-p (session)=
- =ghostherd-backend-spawn (kind plist)= → session (or the host-id
  piece that =ghostherd-spawn= then registers)
- =ghostherd-backend-kill (session)= --- kills the *host* process
- =ghostherd-backend-list ()= → list of host-ids + recipes, for
  restore
- =ghostherd-backend-rename (session new-name)=

Dispatch on =(ghostherd-session-backend session)=, default
='ghostel=. A defcustom =ghostherd-backend= chooses what
=ghostherd-spawn= creates; existing sessions keep the backend they
were born with.

Slice 1 is *only* this extraction. The ERT suite must stay green
with no tmux involved.

**** Session struct

Add to =ghostherd-session=, leave every existing field:

- =backend= --- ='ghostel= or ='tmux=
- =host-id= --- tmux session name, e.g. =gh-a1b2c3d4-reviewer=.
  For the ghostel backend this can equal =id=, or stay nil
- =buffer= becomes optional. =nil= means detached: the agent is
  alive, nobody is looking. That is a new state of the *view*, not
  of the agent. Do not overload =state= for it

=ghostherd--session-live-p= today means "the buffer exists". After
this phase it must mean "the host process is alive". A tmux session
with =buffer= nil is live. A ghostel session whose buffer was
killed is dead, as now. Several callers use live-p as a proxy for
"I can send / read" (=ghostherd-send=, =ghostherd-send-keys=,
=ghostherd-read=, =ghostherd-explain=) --- after the split those
work without a buffer on the tmux backend, so the guard moves to
=ghostherd-backend-live-p=.

=ghostherd-session-recipe= currently documents that agents are
Emacs children and nothing survives a quit. That sentence is
false for the tmux backend; update the docstring when spawn
starts writing the recipe onto the host.

**** Naming and where the recipe lives

tmux targets parse =session:window.pane=. A colon or a dot in
the name is a bug, not a style issue. Hash the expanded project
path (sha1, first 8 hex) and sanitize the session name to
=[A-Za-z0-9_-]=:

: gh-<project-hash>-<sanitized-name>

Use *exact* targets everywhere: =tmux … -t =gh-a1b2c3d4-reviewer=.
Without the leading =:=, tmux prefix-matches, so =gh-abc-rev=
silently operates on =gh-abc-reviewer=.

The tmux session name is not big enough to hold the recipe, and a
sidecar file can be deleted while the process is still running.
Stash the recipe on the session as user options, set via
=call-process= (never a shell string --- same quoting lesson as
=bin/ghostherd=):

: tmux -L ghostherd set-option -t =ID @ghostherd-name reviewer
: tmux -L ghostherd set-option -t =ID @ghostherd-kind claude
: tmux -L ghostherd set-option -t =ID @ghostherd-project /src/app
: tmux -L ghostherd set-option -t =ID @ghostherd-command claude
: tmux -L ghostherd set-option -t =ID @ghostherd-args <one string, see below>
: tmux -L ghostherd set-option -t =ID @ghostherd-notes reviews auth

=args= is a list. Store it as a utf-8 JSON array (the package
already depends on =json-serialize=). Notes can contain newlines;
=call-process= passes the value as one argv, so tmux sees the
newlines and =json-serialize= is not required for that field.
Restore reads them back with =show-options -v=.

**** The tmux server

Dedicated socket, ignore the user's =~/.tmux.conf=:

: tmux -L ghostherd -f /path/to/ghostherd-tmux.conf start-server

Ship a tiny config (new file in the package):

#+begin_src conf
  set -g status off
  set -g prefix None
  set -g mouse off
  set -g destroy-unattached off
  set -g remain-on-exit on
  set -g escape-time 0
  set -g default-terminal "tmux-256color"
#+end_src

=remain-on-exit on= matches today's =ghostel-kill-buffer-on-exit
= nil=: an exited agent stays capturable so the sidebar can show
=dead= with the last screen, instead of the session vanishing
underneath a poll. =ghostherd-kill= is what actually
=kill-session=s.

First spawn starts the server (the =-f= only matters then). If a
stale server was started without this config, recovery is
=tmux -L ghostherd kill-server= --- document that in the
troubleshooting note, do not try to reconfigure a running server
from Elisp.

**** Spawn, kill, rename, respawn

Prefer *direct exec*, not the current shell-then-send delay.
The delay exists because ghostel starts a shell; tmux does not
need one:

: tmux -L ghostherd new-session -d -s ID -c DIR -- COMMAND ARG...

=shell= kind omits =COMMAND=. Then write the recipe options.
Do not pass =-f= on every =new-session=; the server is already
up. Status / prefix come from the config, not from per-session
=set-option= after the fact (those race a fast CLI that already
drew a TUI).

=ghostherd-kill= on a tmux session kills the *host* (and the
view buffer if any), then remhashes. Closing the view buffer
alone must *not* go through =ghostherd-kill= --- see the next
section.

=ghostherd-rename= calls =tmux rename-session= and rewrites
=@ghostherd-name=. =ghostherd-respawn= is still kill + spawn
from the recipe, with =:continue-args= appended when asked.
The recipe now actually outlives Emacs, so respawn after a quit
is "restore already did it" plus a new attach; the interesting
respawn case remains a wedged CLI.

**** Detach is not death  (the easy bug)

This is the load-bearing change. Today:

: ghostel process exits → ghostherd--on-ghostel-exit → state = dead

On the tmux backend, the ghostel buffer's process is
=tmux attach=. Killing that buffer (or the process exiting)
only detaches the client. The agent is still running. If the
exit hook marks =dead=, every "I closed the window" looks like
a crash, and the next poll will flip it back --- or worse, a
notification will fire and a handoff will give up.

So:

- ghostel backend: exit hook marks =dead= (unchanged)
- tmux backend: exit hook clears =session.buffer=, does *not*
  change =state=. Next poll asks the host (=has-session= /
  =#{pane_dead}=)
- A test must fail if a tmux-backed exit hook sets =dead=

How the user detaches: they kill the Emacs buffer. =prefix None=
means there is no =C-b d=. That is intentional --- detach is an
Emacs operation, not a tmux operation.

How the user attaches: =ghostherd-switch= / sidebar =RET= /
=ghostherd-new= with =:display t=. If =session.buffer= is already
live, reuse it. Otherwise start a ghostel buffer whose command
is =tmux -L ghostherd attach -t =ID=. If ghostel can exec a
program directly, do that; if not, the existing
=ghostherd--launch-in-buffer= path is acceptable for the *client
only*, not for the agent.

=ghostherd-new-pair= still splits Emacs windows. Each window is
just another attach client. It does not create tmux panes.

**** Capture, send, send-keys

Detect / explain / read / wait-output all take the screen from
=ghostherd-backend-capture=.

tmux capture:

: tmux -L ghostherd capture-pane -t =ID -p

No =-e= (rules match text, not SGR). No =-J= (these are TUI
agents; the visible cell grid is what the user sees, and joining
wrapped lines invents text that was never on a row). No
=-S -<n>= scrollback --- alt-screen TUIs do not keep their UI
in history, and scraping scrollback is how you match a
permission prompt that scrolled off and is no longer real.
Default capture-pane is the visible pane, which is the thing
=:screen-rules= always wanted.

=ghostherd-send=:

: tmux send-keys -t =ID -l -- TEXT          ; -l = literal
: tmux send-keys -t =ID Enter               ; if submit

=ghostherd-send-keys=: map =ghostherd-key-aliases= onto tmux
key names (=escape= → =Escape=, =return= → =Enter=, =C-c= →
=C-c=, =down= → =Down=). Keep the contract that keys do *not*
mark the session =working=.

All tmux invocations go through one helper that uses
=call-process= and fails visibly. Do not =shell-command=. Check
=exec-path= for =tmux= once at spawn and restore, not on every
poll.

**** Restore

On =ghostherd-mode= enable (and again if the registry is empty
when a command runs), =ghostherd-backend-list= walks:

: tmux -L ghostherd list-sessions -F '#{session_name}'

Keep entries that start with =gh-=, read their =@ghostherd-*=
options, skip any id already in =ghostherd--sessions=, register
the rest with =buffer= nil. A session whose =#{pane_dead}= is
=1= comes back as =dead=, same as an exited ghostel buffer we
have not yet killed.

Notes survive because they live on the session. =manual-state=,
=seen=, =progress-*= do not --- they are Emacs-side and
ephemeral, same as herdr's title tokens. After restore, the
first poll fills =state= from capture.

If tmux is missing or the socket has no server, restore is a
no-op, not an error. The ghostel backend stays usable.

**** OSC and title when detached

No ghostel VT parser runs against a detached session, so OSC
9;4 progress and the =ghostel--title= buffer-local are gone
until someone attaches. That is acceptable: screen rules carry
detection, same as they do when progress is stale.

Title can still be filled without attaching:

: tmux display-message -t =ID -p '#{pane_title}'

tmux already tracks OSC 0/2 as =pane_title=.
=ghostherd--session-title= should prefer the buffer-local when
the view is attached, and fall back to =pane_title= otherwise.
Do not try to parse OSC out of =capture-pane -e= in this phase.

**** Files

Keep the public surface in =ghostherd.el=. Suggested split,
loaded from there:

- =ghostherd-backend.el= --- generics + ghostel implementor
  (the extracted current code)
- =ghostherd-tmux.el= --- tmux implementor + naming + restore
- =ghostherd-tmux.conf= --- the server config above

=ghostherd-tests.el= grows unit tests for naming, recipe
encode/decode, key-name mapping, and the detach-≠-dead hook.
An optional test, skipped unless =executable-find= sees tmux,
round-trips a dummy =echo= session: spawn, capture, send-keys,
list, kill.

=jemacs-ai='s =use-package= form does not need new commands.
=ghostherd-mode= already runs on load; that is the restore hook.

**** Tests that must exist before calling it done

Mirror the way the current suite pins contracts, not mechanisms:

- Naming refuses =:= and =.=; sanitizes everything else
- Recipe JSON round-trips args that contain spaces and quotes
- =ghostherd-backend-capture= is what =ghostherd--detect-state=
  and =ghostherd-explain= call --- a fake backend that returns
  a known string is enough; breaking the call site fails a test
- A tmux-backed session with =buffer= nil is live-p if the host
  says so
- The ghostel exit hook on a tmux-backed session does not set
  =dead= (the easy bug)
- Restore ignores sessions already in the registry, and ignores
  names that do not start with =gh-=
- =ghostherd-send-keys= still does not mark =working=
- Existing 72 ERT tests stay green after slice 1

Do not block on a headless TUI integration test of claude/grok.
That is still the Phase 1 gap.

**** Suggested slices

1. Extract the backend slot, ghostel implementor only. Behaviour
   unchanged, suite green. This is the one that makes the rest
   reviewable.
2. tmux host: spawn / kill / list / capture / send / send-keys /
   restore. Headless sessions appear in the sidebar and can be
   messaged with no attach. New tests above, plus the optional
   tmux smoke if present.
3. Attach: visit opens a ghostel client; kill-buffer detaches;
   exit hook fixed; title from =pane_title= when detached;
   =ghostherd-new-pair= still just two Emacs windows.
4. Rename / respawn / remain-on-exit dead rows / dogfood /
   =:screen-rules= against real capture-pane output (this is
   also the leftover Phase 1.1 data pass).

- Windows as a navigation layer, panes as a layout layer
- Loading the user's tmux.conf, or sharing the default socket
- Phone / SSH thin client, herdr-compatible socket server
- Making tmux the default backend
- Asking ghostel for a VT grid API --- worth doing later as
  3a, not a dependency of this plan

* Architecture sketch

#+begin_src text
  UI: sidebar | consult | modeline | alert
           │
  Control: spawn kill rename prompt message wait
           │
  Detect:  timer + screen rules + ghostel-exit / OSC hooks
           │
  Runtime: ghostel buffers (real PTYs), one per session
#+end_src

Sessions live in =ghostherd--sessions= (id → =ghostherd-session= struct).
Buffer-local =ghostherd-session-id= links the PTY buffer back to the registry.

Phase 3 inserts a backend slot between Detect/Control and Runtime.
The ghostel path above stays as one implementor; tmux is the other
(=capture-pane= / =send-keys=, process not an Emacs child, attach
optional). See the Phase 3 implementation plan.

* Design decisions log

| Decision              | Choice                                      | Why                                      |
|-----------------------+---------------------------------------------+------------------------------------------|
| Lifetime              | Bound to Emacs first                        | Simpler; detach is Phase 3               |
| UI                    | Sidebar *and* consult                       | Herd overview + fast jump                |
| Agents                | claude, grok, agy (+ shell)                 | What this machine runs                   |
| Multi-agent           | First-class (pair + message)                | Review / implement split is common       |
| Spawn strategy        | Shell then send CLI line                    | Matches “terminal owns agent”; flexible  |
| State authority       | Screen rules + exit hooks                   | No per-CLI lifecycle plugins yet         |
| Blocked policy        | Strict (miss rather than false positive)    | Same as herdr                            |
| Notify                | Reuse ghostel hooks + alert                 | No parallel notifier                     |
| Kill-on-exit          | Off for herd buffers                        | Keep =dead= rows visible                 |
| Phase 3 host          | tmux as headless PTY, 1 session per agent   | Capture + survive; not a second mux      |
