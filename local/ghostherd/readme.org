#+TITLE: ghostherd

Manage AI coding-agent CLIs inside [[https://github.com/dakra/ghostel][ghostel]] terminals — a herdr-inspired
control plane bound to the Emacs session.

* Features (Phase 1)

- Spawn *claude* / *grok* / *agy* (or a plain shell) as named sessions
- Multiple concurrent agents per project (e.g. implementer + reviewer)
- Sidebar (=ghostherd-sidebar=) + consult switcher (=ghostherd-switch=)
- State polling: =working= / =blocked= / =idle= / =done= / =dead=
- Notifications via =alert= (config uses =osx-notifier=)
- Inter-agent messaging: =ghostherd-message=, =ghostherd-prompt=, =ghostherd-read=, =ghostherd-wait=
- Agents can call herd commands via =ghostel_cmd= (whitelisted; ghostel
  backend only --- see "Hosts")

* Hosts (Phase 3)

An agent has to run *somewhere*, and ghostherd no longer assumes where.
Everything above the host slot — detection, messaging, handoff, the
sidebar — is written against six capabilities, and two implementors
provide them.

| Capability            | =ghostel=                    | =tmux=                        |
|-----------------------+------------------------------+-------------------------------|
| Screen                | buffer text                  | =capture-pane=                |
| Type text / keys      | =ghostel-paste-string= etc.  | =send-keys= / =paste-buffer=  |
| Alive?                | buffer is live               | session is on the socket      |
| Exited?               | process sentinel             | =#{pane_dead}=                |
| Survives Emacs        | no — agent is an Emacs child | yes                           |
| Costs a nested VT     | no                           | only while you are looking    |

#+begin_src emacs-lisp
  (setq ghostherd-backend 'tmux)      ; where new agents start
#+end_src

Only =ghostherd-spawn= reads it. A session keeps the backend it was born
with, so switching does not strand the herd you already have, and
=ghostherd-restore= sweeps *every* backend rather than just the current
one.

** Why tmux, and why not as a multiplexer

Survival is the smaller prize. The larger one is =capture-pane=: state
detection used to scrape the Emacs buffer, which is why so much of Phase
1.1 went into fighting alt-screen behaviour, resize repaints and what
ghostel had or had not rendered yet. capture-pane reads the pane
directly, works when nothing is attached, and does not care how ghostel
draws.

So tmux is here as a *named, detachable PTY that can dump its own
screen*. One ghostherd session = one tmux session on a dedicated socket
(=tmux -L ghostherd=), one window, one pane, =status off=, =prefix
None=. Not windows-as-tabs, not panes-as-layout: either would put a
third navigation layer inside ghostel, and Emacs already multiplexes.
Your own =tmux= on the default socket is untouched.

** Attach is optional

Nobody needs to be attached for the herd to work. Detection reads
=capture-pane=; input goes through =send-keys=. =RET= in the sidebar,
=ghostherd-switch= and =ghostherd-visit= are the only things that run
=tmux attach=, inside a ghostel buffer. Killing that buffer detaches;
the agent keeps running.

*Detaching is not dying,* and that is the one bug this phase had to get
right. The ghostel process in an attached buffer is =tmux attach=, so
its exit means a client went away. Marking the session =dead= there
would fire a notification, make a handoff give up, and be reverted by
the next poll anyway. The exit hook therefore asks
=ghostherd-backend-view-is-host-p= first, and an unknown backend gets
the safe answer.

Both listings say so. The switcher annotates such a session =detached=;
the sidebar appends =ghostherd-detached-glyph= to its state glyph, so a
row reads =○▪= rather than =○=. It is a state of the *view*,
deliberately not of =state= --- an agent is working or blocked whether
or not anyone is watching.

The mark rides in the spare character of the two-wide glyph column
instead of getting a column of its own. At the default sidebar width
there is no room for another column, so a =View= column would be fitted
away in exactly the situation that needs it. Marking the detached rows
rather than the attached ones also keeps it silent on the ghostel
backend, where a registered session always has its buffer.

This was originally left out of the sidebar on the grounds that the
switcher is where you choose an agent. That was wrong, and the first
run of T10 found it: the sidebar is the herd *overview*, and an
overview that cannot distinguish a herd running headless from one you
are watching is not describing the herd.

** Surviving Emacs

The recipe — kind, project, command, args, notes — is stashed on the
tmux session itself as =@ghostherd-*= user options, not in a sidecar
file (which can be deleted while the process it describes is still
running) and not in the session name (which is not big enough).
=ghostherd-mode= runs =ghostherd-restore= on enable, so a herd left by a
previous Emacs comes back detached and the first poll fills in its
state.

What does not come back is Emacs-side and never could: a manual state
override, whether a session has been seen, the last OSC progress
report. Notes do, because they were written onto the host.

** Two tmux details worth writing down

- *Targets are =\=NAME:=, always.* Without the =\== tmux prefix-matches,
  so =gh-abc-rev= silently drives =gh-abc-reviewer=. Without the
  trailing colon, the commands that parse a *pane* target — =set-option=,
  =capture-pane=, =send-keys= — resolve a bare =\=NAME= against the
  current session instead. =display-message= is the one that makes this
  worth remembering: given =\=NAME= it prints an empty format rather
  than failing.
- *The config goes on every invocation.* tmux reads =-f= once, in
  whichever process starts the server, and the only ghostherd command
  that can start one is =new-session=. Passing it always puts =status
  off= and =remain-on-exit on= in force *before* the first pane exists —
  a =set-option= after the fact races a CLI that has already drawn its
  TUI at the wrong height. It also means no server lingers between
  herds: tmux exits with its last session, and the next spawn brings it
  back configured.

Recovery for a server started without the config is =tmux -L ghostherd
kill-server=. Reconfiguring a running server from Elisp is not.

** Reloading over a live herd

Phase 3 added two slots to =ghostherd-session=. Emacs does not migrate
structs that already exist, so a session created before the reload is
read through the new accessors with every field after the new slot
shifted along: =backend= comes back holding a project path.

It is worth knowing what that looks like, because the symptom names
neither the cause nor the cure:

#+begin_example
  Error during redisplay: (eval (ghostherd--mode-line-segment) t) signaled
  (cl-no-applicable-method ghostherd-backend-live-p "/src/app/" #s(ghostherd-session …))
#+end_example

The cure is to clear the registry, which deregisters the sessions and
leaves their buffers and agents alone:

#+begin_src emacs-lisp
  (clrhash ghostherd--sessions)
#+end_src

Do that *before* reloading, not after. Structs cannot be versioned
retroactively, so this could not be repaired --- only named:
=ghostherd--backend-of= now checks that a backend is a symbol and says
the above in one sentence.

Two things were genuinely wrong, though, and are fixed:

- The mode-line segment used to sweep the registry, which was free when
  a host check was =buffer-live-p= and is not once one can run a
  subprocess. Redisplay is no place for I/O, and no place to find out
  that the I/O failed --- a segment that signals breaks the whole
  frame, repeatedly. It now only reads. The poll timer still sweeps.
- =ghostherd--ensure-sessions= treated an unanswerable host check as
  "gone" and pruned. A host is far likelier to be briefly unreachable
  than actually absent, so that deleted the herd instead of reporting
  it. It now keeps what it cannot ask.

** What it costs

Two terminal emulators nested — tmux's VT inside ghostel's — but only
for the agent you are actually looking at.

=ghostel_cmd= does not work inside a tmux-hosted agent: ghostel's shell
integration is installed into the shell *ghostel* spawns, and here it
spawns =tmux attach=. Use =bin/ghostherd= instead, which is what it was
for.

* Inter-agent communication

Herdr exposes pane/agent primitives over a socket. ghostherd mirrors the
useful subset in Elisp (and via =ghostel_cmd= from inside an agent shell).

** Elisp

#+begin_src emacs-lisp
  ;; Submit work to the reviewer and wait until settled
  (ghostherd-prompt "reviewer" "Review the current diff for security issues" t 180)

  ;; Message with attribution (from implementer → reviewer)
  (ghostherd-message "implementer" "reviewer"
                     "Please review commits on this branch."
                     :submit t)

  ;; Read another agent's recent screen
  (ghostherd-read "reviewer" 80)

  ;; Wait for blocked/idle/done
  (ghostherd-wait "reviewer" '(blocked idle done) 120)
#+end_src

** From an agent shell (ghostel_cmd)

When shell integration is active and the command is whitelisted:

#+begin_src bash
  ghostel_cmd ghostherd-list
  ghostel_cmd ghostherd-state reviewer
  ghostel_cmd ghostherd-prompt reviewer "Review the diff"
  ghostel_cmd ghostherd-message reviewer "Please review" implementer
  ghostel_cmd ghostherd-read reviewer 60
#+end_src

=ghostherd-list= and =ghostherd-state= emit JSON:

#+begin_example
  [{"name":"reviewer","kind":"grok","state":"blocked","reason":"Approve",
    "project":"/src/app/","notes":"reviews auth","age":"3m"}]
#+end_example

Not for tidiness --- the previous tab/equals format had no escaping, and two
of the fields are free text. A note containing a tab or newline turned one
record into several, and =reason= holds a raw =:screen-rules= regexp, which
can contain anything. An unknown session reports ={"error":...}= rather than
a prose string, so a caller can tell a failure from a session that happens
to be named like one.

Typical workflow:
1. =SPC a h 2= → implementer (claude) | reviewer (claude or grok)
2. Work in implementer
3. =SPC a h m= → message reviewer with a review request
4. =SPC a h .= when reviewer is blocked / done

* Talking to an agent vs operating it

Two different things, and only the first existed before Phase 2.5.

=ghostherd-send= / =ghostherd-prompt= paste *text* and optionally press
Return. That is how you talk *to* an agent, and it assumes the agent is
sitting there waiting for input.

=ghostherd-send-keys= sends *keystrokes*. Escaping a runaway generation,
answering an arrow-driven permission menu, sending EOF --- none of these are
text. Pasting the characters =esc= just feeds the agent a word.

#+begin_src emacs-lisp
  (ghostherd-interrupt "reviewer")          ; Escape -- "esc to interrupt"
  (ghostherd-abort "reviewer")              ; C-c
  (ghostherd-answer "reviewer" 2)           ; pick option 2 of a menu
  (ghostherd-send-keys "reviewer" "tab" "down" "return")
#+end_src

Three things worth knowing:

- Keys do *not* mark the session =working=, though text input does. The usual
  reason to send a key is to make the agent *stop*; claiming it just started
  would be backwards. The next poll reports what actually happened.
- =ghostherd-answer= presses Up several times before descending. The
  highlighted option is not necessarily the first, and counting down from
  wherever the cursor happens to be picks the wrong answer. Some CLIs accept
  the digit as text and some only respond to arrows; there is no way to tell
  from outside, and arrows work for both.
- Friendly names (=esc=, =C-c=, =down=) are mapped in
  =ghostherd-key-aliases=. Anything unlisted is passed through to
  =ghostel-send-key= unchanged, so its full vocabulary stays reachable.

* Waiting

=ghostherd-wait= watches the state machine, which only knows the five states
the screen rules can produce. Plenty of things worth waiting for have no
state of their own --- a test summary, a specific error, the agent naming
the file it just wrote.

#+begin_src emacs-lisp
  (ghostherd-wait "reviewer" '(blocked idle done) 120)   ; by state
  (ghostherd-wait-output "reviewer" "[0-9]+ failures" 300)  ; by output
  (ghostherd-wait-output "reviewer" "deployed" 60 t)     ; nil instead of error
#+end_src

- Returns the matched text; signals on timeout unless NOERROR, because
  scripts branching on "did it happen" should not have to wrap every call in
  =condition-case=.
- Checks *before* sleeping. Output can arrive between whatever triggered the
  wait and the wait itself, and a first check one interval late would miss
  it.
- Gives up when the session dies. A dead agent will never produce the text;
  waiting out the full timeout for it is just a hang.
- Matching is *case-sensitive*, unlike =:screen-rules= --- see below.

** Known issue: rule matching case

=:screen-rules= use =string-match-p= under whatever =case-fold-search=
happens to be at poll time, which is not something the rule author controls.
=ghostherd-output-matches= binds it to nil deliberately so a regexp means
what it says. The rules should probably do the same, but changing it would
silently alter what every existing pattern matches, so it wants a dogfood
pass rather than a quiet fix.

* Handing work to another agent

=ghostherd-handoff= is the pipeline primitive: message an agent, watch it,
report.

#+begin_src emacs-lisp
  ;; from the implementer, hand a review request to the reviewer
  (ghostherd-handoff "reviewer" "Review the diff on this branch"
                     "implementer")

  ;; with your own completion handler
  (ghostherd-handoff "reviewer" "Run the suite" "user" 300
                     (lambda (session state)
                       (when (eq state 'done)
                         (pop-to-buffer (ghostherd-session-buffer session)))))
#+end_src

*It is asynchronous, deliberately.* =ghostherd-wait= blocks in a =sit-for=
loop, which would freeze you out of the very editor you are meant to keep
working in while the other agent runs --- and orchestrating without sitting
and watching a pane is the entire point of this phase. There is a test that
fails if a handoff ever calls =sit-for=.

Two things it has to get right:

- *Grace window.* An agent does not start the instant it is handed
  something: the CLI has to wake up and print, and until it does the screen
  rules still see the idle prompt from before. Without
  =ghostherd-handoff-grace= the watch would report completion immediately,
  every time.
- *One watch per agent.* Handing off to an agent that is already being
  watched replaces the watch instead of stacking a second timer on it, and a
  callback that throws cancels the watch rather than leaving it polling
  forever.

* From a shell (=bin/ghostherd=)

=ghostel_cmd= reaches the herd from inside an agent's own terminal. This is
for everywhere else --- a Makefile, a git hook, a CI step:

#+begin_src bash
  bin/ghostherd list                       # JSON
  bin/ghostherd state reviewer
  bin/ghostherd prompt reviewer "Run the suite"
  bin/ghostherd handoff reviewer "Review the diff" implementer
  bin/ghostherd keys reviewer down down return
  bin/ghostherd interrupt reviewer
#+end_src

=GHOSTHERD_SOCKET= picks an emacsclient socket; =GHOSTHERD_DRY_RUN= prints
the elisp instead of running it, which is how the quoting is tested.

Two things it has to get right, both learned the hard way:

- *Quoting.* Every argument is free text --- a prompt can contain quotes,
  backslashes and newlines --- so it is escaped into an Emacs Lisp string
  literal rather than interpolated. Verified by round-tripping through the
  Emacs reader, not by eyeballing.
- *Output goes through a temp file, and the write is pinned to UTF-8.*
  =emacsclient -e= prints the *Lisp representation*, so JSON would come back
  double-escaped as ="[{\"name\":...}]"=. Writing to a file avoids that ---
  but agent output is full of non-ASCII (box drawing, the =❯= in a
  permission prompt), and =write-region= without an explicit coding system
  calls =select-safe-coding-system=, which *prompts*. In batch that is an
  error; in a daemon it blocks forever on a minibuffer nobody can answer and
  wedges the server for every later call too. That is not hypothetical: it
  is what the first version did.

* Notifications (ghostel hooks)

ghostherd reuses ghostel's process lifecycle rather than inventing a
parallel notifier:

| Signal                       | Source                        | Herd action            |
|------------------------------+-------------------------------+------------------------|
| View process exit            | =ghostel-exit-functions=      | =dead= *only* if the view is the host |
| Agent exit, tmux backend     | =#{pane_dead}= at poll        | state → =dead=, notify |
| OSC 133 command start/finish | =ghostel-command-*-functions= | shell kind state hints |
| OSC 9;4 progress             | =ghostel-progress-function=   | → =working= (+ %)      |
| OSC 2 title                  | =ghostel--title=              | sidebar Title column   |
| Screen rules (poll)          | timer                         | working/blocked/idle   |
| Desktop notify               | =alert= / =osx-notifier=      | blocked / done / dead  |

Everything in that table except the last two rows needs an attached
ghostel buffer, so on the tmux backend a detached session gets neither
OSC progress nor an OSC 2 title from ghostel. That is fine and was
expected: screen rules carry detection on their own, exactly as they do
when a progress report has gone stale, and the title is still readable
as =#{pane_title}=, which tmux tracks from the same escape sequence.

Two notes on the OSC integrations, because neither is a hook:

- =ghostel-progress-function= is a single global function, very likely
  someone's spinner. ghostherd saves and *chains to* the previous value, and
  restores it when =ghostherd-mode= is disabled. Its handler runs
  synchronously on ghostel's VT-parser callpath, where slow work stalls
  terminal output, so it only records the report; the poll path decides what
  it means.
- The title is read straight off buffer-local =ghostel--title=. Going through
  =ghostel-buffer-name-function= (ghostel's title→buffer-name mapping) would
  fight ghostherd's own buffer naming.

* Why is it in that state? (=ghostherd-explain=)

=e= in the sidebar, or =M-x ghostherd-explain=. Shows the scraped tail, every
=:screen-rules= pattern that matched it, and which one won:

#+begin_example
  agy-review  (agy)

    state    ○ idle
    reason   —
    buffer   *ghostherd:agy-review*

  Matches, in precedence order (blocked > working > idle):

    blocked  ->  Do you want to proceed
    working      Running
    working      esc to interrupt
    idle         ^>

  Only the first line wins.  A rule listed under a
  higher-precedence state shadows every rule below it.
#+end_example

Rule tuning is guesswork without this. A false =blocked= looks exactly like a
real one until you can see *which* pattern matched, and that the agent had
merely printed the words rather than stopped on a prompt.

** Detection notes per CLI

Screen rules are heuristics against a UI that changes between releases, so
record what was observed against which version. Prefer a *missed* =blocked=
over a false one.

| CLI    | Version tested | Known false positive / miss | Fix applied |
|--------+----------------+-----------------------------+-------------|
| claude |                |                             |             |
| grok   |                |                             |             |
| agy    | 1.1.12         |                             |             |

Agent buffers set =ghostel-kill-buffer-on-exit= to nil so an exited
session stays visible as =dead= until you kill it from the herd.

* Per-project defaults

Drop this in a project's =.dir-locals.el= and =ghostherd-new= preselects the
kind and prefills the args:

#+begin_src emacs-lisp
  ((nil . ((ghostherd-project-kind . claude)
           (ghostherd-project-args . ("--permission-mode" "acceptEdits")))))
#+end_src

Both are marked =safe-local-variable= for their expected shapes, so no
prompt. They are read *by directory* rather than from the current buffer:
=ghostherd-new= is often invoked from the sidebar or another non-file buffer,
which never picked up the project's dir-locals at all.

Resolved before the kind prompt so the project can preselect it. Changing
the directory later in the same prompt sequence does not re-read --
re-prompting for a kind you already answered would be worse than stale.

* Config knobs

#+begin_src emacs-lisp
  (setq ghostherd-default-kind 'claude
        ghostherd-poll-interval 1.5
        ghostherd-spawn-delay 0.8
        ghostherd-notify-on-blocked t
        ghostherd-sidebar-side 'left)

  ;; OSC 9;4 progress as evidence of `working'
  (setq ghostherd-use-osc-progress t
        ghostherd-progress-ttl 5)         ; seconds a report stays trusted

  ;; OSC 2 title as a sidebar column.  Columns are fitted to the sidebar
  ;; width, and Title outranks Project, so in a narrow sidebar this trades
  ;; the project path for the title rather than overflowing.
  (setq ghostherd-sidebar-show-title nil)

  ;; Host for agents started from now on.  Existing sessions keep the
  ;; backend they were born with.
  (setq ghostherd-backend 'tmux
        ghostherd-tmux-socket "ghostherd"      ; never the default socket
        ghostherd-tmux-default-size '(120 . 40) ; size while detached
        ghostherd-tmux-status-ttl 1.0          ; one list-panes per tick
        ghostherd-tmux-config nil)             ; nil = generate one

  ;; Permanent default args example:
  (setf (alist-get 'claude ghostherd-agent-specs)
        (plist-put (alist-get 'claude ghostherd-agent-specs)
                   :args '("--permission-mode" "acceptEdits")))
#+end_src

* Testing

** Automated (=ghostherd-tests.el=)

#+begin_src bash
  cd local/ghostherd
  emacs --batch -L . -l ghostherd.el -l ghostherd-tests.el \
        -f ert-run-tests-batch-and-exit
#+end_src

Covers the parts that need no PTY: rule matching and precedence, OSC

column fitting, title filtering, naming and age formatting.

Phase 3 added the host slot, and the way it is tested is the point: a
=fake= backend answers with a known screen, so the tests pin the *call
sites* rather than either implementor. Rewiring detection back to a
buffer fails a test with no tmux and no PTY anywhere near it. For tmux
itself, =ghostherd-tmux--call= is the single seam every invocation
passes through, so stubbing it pins the actual command lines --- which
is where this backend's mistakes live: a missing =\==, a =paste-buffer=
without =-r=, a =capture-pane= that grew a =-J=.

One test runs against a real tmux (spawn → capture → send → restore →
kill) and is skipped when tmux is absent. It is the only thing that
would catch tmux changing its mind about a flag.

The suite was mutation-checked rather than merely run. Breaking the
blocked-beats-progress rule, the progress chaining, the column budget,
the mandatory-column flag and the title filter each fail a test; so do
marking a detached view as =dead=, dropping the exact-target =\==,
joining wrapped lines in a capture, letting =paste-buffer= turn
newlines into submissions, hashing a project root with and without its
trailing slash, and letting restore clobber a session it already knows.

That exercise has now found two real defects. The first was a floor on
the column budget that made the mandatory flag unreachable. The second
was an off-by-one in the new screen tail: a capture of exactly N rows
ends in a newline, so splitting it yields N+1 fields and taking the
last N drops the *first* line --- which is how the first thing an agent
printed goes missing from a screen that is plainly still showing it.

** What a snapshot can and cannot hold

On the ghostel backend, agents are Emacs child processes: when Emacs
exits, they exit. So the most that can be persisted is the *recipe* ---
kind, directory, args, notes --- which is exactly what
=ghostherd-session-recipe= returns. (Phase 3 changed the first sentence,
not the second: on the tmux backend the agent itself survives, and the
same recipe is written onto the host so =ghostherd-restore= can rebuild
the session around a process that never stopped.)

The conversation is not in the recipe, and never can be. But it is not lost
either: it lives in the CLI's own store, and each CLI has a flag to reopen
it. That flag is declared per kind as =:continue-args= in
=ghostherd-agent-specs= rather than hardcoded, so a CLI without one is
representable (=shell= has none) and respawn refuses instead of silently
starting cold.

=ghostherd-respawn= therefore gets most of the way to "my herd came back"
with no new dependency: it frees the old buffer and id, then respawns from
the recipe, appending =:continue-args= when asked. Note *appending* --- a
session spawned with =--model= must come back on that model, not the
default.

Surviving an Emacs quit for real needed a process that is not an Emacs
child --- which is Phase 3, and is what =ghostherd-backend= now selects.
Respawn stays useful either way: after a restart on tmux, restore has
already done the work, so the interesting respawn case is the one it
always was --- a wedged CLI.

* Architecture sketch

#+begin_src text
  UI: sidebar | consult | modeline | alert
           │
  Control: spawn kill rename prompt message wait handoff
           │
  Detect:  timer + screen rules + ghostel-exit / OSC hooks
           │
  Host:    capture · send-text · send-keys · live-p · exited-p
           spawn · kill · rename · list · view          ← the slot
           │                              │
  Runtime: ghostel buffer (PTY)      tmux session (PTY, on -L ghostherd)
           agent = Emacs child       agent outlives Emacs; view optional
#+end_src

Sessions live in =ghostherd--sessions= (id → =ghostherd-session= struct).
Buffer-local =ghostherd-session-id= links a view buffer back to the
registry — a *view*, since on the tmux backend a session may have none.

Files:

| File                  | Holds                                                 |
|-----------------------+-------------------------------------------------------|
| =ghostherd-backend.el= | session struct, registry, the slot, ghostel implementor |
| =ghostherd-tmux.el=    | tmux implementor, naming, recipe stash, restore       |
| =ghostherd.el=         | everything else — detection, UI, messaging, commands  |

Two deviations from the Phase 3 plan below, both forced:

- The ghostel implementor lives in =ghostherd-backend.el= *with* the
  struct rather than being extracted around it. Splitting them the
  other way is circular: the implementor needs the accessors, and the
  struct is what the whole package is about.
- The tmux server config is *generated* into
  =~/.emacs.d/ghostherd-tmux.conf= from a string, not shipped as a file
  beside the source. A lone =.conf= is not on any package manager's
  default file list, so the shipped version works from a checkout and
  silently does not once built — and a missing config means
  =remain-on-exit off=, which fails a long way from its cause.

* Design decisions log

| Decision              | Choice                                      | Why                                      |
|-----------------------+---------------------------------------------+------------------------------------------|
| Lifetime              | Bound to Emacs first, then a host slot      | Simpler first; detach became Phase 3     |
| UI                    | Sidebar *and* consult                       | Herd overview + fast jump                |
| Agents                | claude, grok, agy (+ shell)                 | What this machine runs                   |
| Multi-agent           | First-class (pair + message)                | Review / implement split is common       |
| Spawn strategy        | Shell then send CLI line                    | Matches “terminal owns agent”; flexible  |
| State authority       | Screen rules + exit hooks                   | No per-CLI lifecycle plugins yet         |
| Blocked policy        | Strict (miss rather than false positive)    | Same as herdr                            |
| Notify                | Reuse ghostel hooks + alert                 | No parallel notifier                     |
| Kill-on-exit          | Off for herd buffers                        | Keep =dead= rows visible                 |
| Phase 3 host          | tmux as headless PTY, 1 session per agent   | Capture + survive; not a second mux      |
| Backend dispatch      | On a symbol, not a struct subtype           | One session type; the host is a field    |
| Backend default       | =ghostel=, per session at birth             | Switching must not strand a live herd    |
| tmux spawn            | Direct exec, no shell                       | No quoting, no spawn-delay guesswork     |
| tmux recipe           | =@ghostherd-*= session options              | A sidecar file outlives nothing reliably |
| tmux config           | Generated from a string, =-f= every call    | A shipped .conf does not survive a build |
| View vs state         | =buffer= nil means detached, not dead       | Closing a window is not a crash          |
