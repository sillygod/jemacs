#+TITLE: ghostherd — roadmap

What shipped in each phase, what is left, and what was decided against.
The manual is [[file:../readme.org][readme.org]]; the reasoning behind the choices is in
[[file:design.org][design.org]].

Phase 1 (this tree) is intentionally small: spawn, list, switch, state,
notify, pair layout, message/prompt/read/wait.

* Phase 1.1 — Stabilize detection (next dogfood pass)

Goal: make state trustworthy for daily use without false blocked spam.

- [X] =ghostherd-explain= (like herdr =agent explain=): show last tail
  snippet + which rule matched
- [X] OSC progress (=ghostel-progress-function=) → force =working= + %
- [X] OSC title → sidebar summary column (opt-in; see the width note under
  Config knobs)
- [ ] Tune =:screen-rules= per CLI after T4 sessions — needs real dogfood
  data; =ghostherd-explain= produces it live, and the herd log now keeps
  the screen behind every =blocked= so it accumulates unattended.
  *Demoted rather than done*: Phase 3.5 lets an agent report its own
  state, so for a CLI with lifecycle hooks the rules became the fallback
  instead of the authority. Still worth doing for the CLIs that have no
  hooks — which is why the dogfood log stays open
- [X] A state reason says what the agent asked rather than which regexp
  matched, so a notification is actionable without visiting the agent
- [X] =ghostherd-log=: what the herd did while you were away, with the
  screen behind each =blocked= kept for tuning
- [X] Rules match case-sensitively rather than under whatever
  =case-fold-search= the poll timer happened to fire under.  See "Rule
  matching case" in [[file:design.org][design.org]]; the patterns themselves are unchanged,
  and that is the part to watch
- [ ] Document known false positives per agent version — the table is under
  "Detection notes per CLI" in [[file:../readme.org][readme.org]]

- [X] Sidebar columns are fitted to the window instead of overflowing it.
  They used to be a fixed vector needing ~70 characters against a default
  width of 36, so every row wrapped. =ghostherd--sidebar-column-specs= now
  lists candidates most-useful-first and the widest, least informative ones
  (=Project=, then =Kind=) drop out when there is no room. The fit follows a
  manual resize, not just =ghostherd-sidebar-width=.

* Phase 2 — Usability

Goal: less friction for multi-agent day-to-day work.

- [-] Layout presets beyond pair (1+2 grid, focus agent only) --- *decided
  against*. =ghostherd-new-pair= covers the split that actually gets used,
  and window layout is something Emacs already has better tools for than a
  herd manager should reimplement.
- [X] Session notes editable from sidebar (=c=); role shown in switcher
- [X] Per-project default kinds/args via dir-locals
- [X] Consult annotations (kind, project, age, notes) --- candidates are
  now bare names with the detail in an affixation, so typing matches the
  name instead of whatever happened to be concatenated into the string
- [X] ERT unit tests for pure helpers (rules, naming, format) ---
  =ghostherd-tests.el=, mutation-checked

- [X] =ghostherd-respawn= (=R= in the sidebar) --- was two roadmap items,
  "persist snapshot" and "restart-agent", which turned out to be the same
  thing
- [X] Session list is a posframe overlay when posframe is available,
  falling back to the side window. Same buffer, same keys; Esc
  dismisses. Visit / explain / log leave the overlay so they do not
  display inside the child frame.

* Phase 2.5 — Richer automation (herdr-like control)

Goal: scripts and agents can orchestrate without focusing panes.

- [X] =ghostherd-wait-output= (regex on buffer tail, timeout)
- [X] =ghostherd-send-keys= (esc, ctrl+c, arrows, tab) --- plus
  =ghostherd-interrupt= / =ghostherd-abort= / =ghostherd-answer=
- [X] Pipeline helper: implement → message reviewer → wait → notify
  (=ghostherd-handoff=)
- [X] Structured JSON listing for =ghostherd-cmd-list= / =ghostherd-cmd-state=
- [X] =emacsclient= CLI wrapper (=bin/ghostherd=)

* Phase 3 — tmux as a headless PTY host  *(done)*

Goal: read the agent's screen out of band, and let sessions outlive Emacs.

How it behaves is in [[file:../readme.org][readme.org]] under "Hosts", where someone using
the thing will find it; why it is shaped that way is in [[file:design.org][design.org]].
This is the record of what shipped and what is left.

** What shipped

- [X] The host slot as *capabilities, not product names*: =capture=,
  =send-text=, =send-keys=, =live-p=, =exited-p=, =title=, =spawn=,
  =kill=, =rename=, =view=, =list=. =cl-defgeneric= dispatching on the
  backend symbol, with =ghostherd--host-*= wrappers that read it off
  the session
- [X] The ghostel path extracted behind that slot with no behaviour
  change — the 72 Phase 2.5 tests stayed green through slice 1
- [X] tmux implementor: dedicated socket, one session per agent,
  =status off= / =prefix None=, direct exec (no shell, so no
  =ghostherd-spawn-delay= guesswork)
- [X] The recipe stashed on the tmux session as =@ghostherd-*= options;
  args as JSON, so a =--system-prompt= full of quotes round-trips
- [X] =ghostherd-restore= on =ghostherd-mode=, sweeping every backend
- [X] Attach on visit only; =ghostherd-visit= is the single entry point
  and =ghostherd-new-pair= is still just two Emacs windows
- [X] Detach ≠ death (see "Attach is optional" in [[file:../readme.org][readme.org]])
- [X] =dead= rows survive: =remain-on-exit on= mirrors what
  =ghostel-kill-buffer-on-exit= nil already did for the other backend
- [X] 28 new ERT tests, mutation-checked; plus a real-tmux round trip
  that is skipped when tmux is absent

** What is left

- [X] The attach path, T10.  Spawn detached, detect over =capture-pane=,
  kill the buffer, watch the row stay, =RET= back onto the same agent.
  =ghostel-exec= needs the compiled module, so this could only ever be
  a manual check; it passed.  T11 (surviving an Emacs quit) and T12
  (working → detach → still working) are still worth a run
- [ ] Tune =:screen-rules= against actual =capture-pane= output. This
  is the leftover Phase 1.1 data pass, and it is *why* Phase 3 was
  worth doing first: the tuning loop was only hard because the thing
  being scraped was a rendering of a rendering
- [X] Decided: =jemacs-ai= opts in with =(setq ghostherd-backend 'tmux)=.
  The package default stays =ghostel=, which needs nothing installed

** Deliberately not done

- Windows as a navigation layer, panes as a layout layer
- Loading the user's =tmux.conf=, or sharing the default socket
- Phone / SSH thin client, herdr-compatible socket server
- Making tmux the *package* default.  A package should work with
  nothing installed, and the ghostel backend does.  Opting in belongs
  in a config that knows the machine has tmux --- =jemacs-ai= sets
  =ghostherd-backend= to =tmux=, because a survival feature that only
  works when you remembered to switch it on beforehand does not cover
  the restart you did not expect
- A dtach implementor: it cannot =capture=, so it buys only the
  smaller half of the prize
- Asking ghostel for a VT grid API. Still worth doing later as 3a —
  capture from a real grid, not from buffer text, would be the larger
  prize *without* the nested VT, and persistence could then sit on a
  thinner host. Until it exists, tmux is the one widely installed tool
  that does both jobs.

* Phase 3.5 — The agent as an authority on itself  *(done)*

Goal: stop guessing =blocked= and =done= from a rendering of a screen,
for the CLIs that already know.

How to use it is in [[file:../readme.org][readme.org]] under "Agents that report themselves" and
"Which agent am I?"; why it is shaped that way is in [[file:design.org][design.org]] under
"Why a report is not a mark".

** What shipped

- [X] *Identity at spawn.* =GHOSTHERD_SESSION= / =GHOSTHERD_BACKEND= /
  =GHOSTHERD_SOCKET= in the agent's environment, from one list, on both
  backends. Nothing could tell a process afterwards, which is why every
  idea below was impossible before it
- [X] =self= everywhere: in =bin/ghostherd= (substituted by the shell,
  the only place that has the variable) and in the =ghostel_cmd=
  commands (from the calling terminal's buffer). Plus =ghostherd whoami=
- [X] A message from an agent is attributed to *that agent*.
  =bin/ghostherd message TO TEXT= defaulted the sender to ="user"= --- a
  lie whenever the caller was an agent, and it had no way to say
  otherwise
- [X] =ghostherd-report= / =ghostherd report self STATE [WHY]=: the third
  state authority, with a TTL rather than the stickiness of
  =ghostherd-mark-state=. Precedence table in the readme; a =blocked=
  rule on the screen still beats it, and a =working= screen vetoes a
  claimed =blocked=
- [X] =ghostherd-explain= shows the report, its age, and whether it
  expired --- a report is the one authority that leaves no trace on the
  screen printed below it
- [X] =done= means "finished while you were not looking" for a report
  too, not only for the promotion path that used to own the rule
- [X] A rename carries the report (and the input grace, and the settle
  timestamp) to the new id instead of dropping them
- [X] 20 new ERT tests, mutation-checked; plus a real round trip through
  tmux, emacsclient and =bin/ghostherd=

** What is left

- [ ] Dogfood the claude hook wiring for a few days: the TTL and the
  =working=-vetoes-=blocked= rule are both judgement calls that want log
  evidence, and =ghostherd-explain= now prints exactly what is needed to
  argue about them
- [ ] grok and agy: find out whether they have a hook mechanism at all.
  The readme documents claude's because it is the one that does

** Deliberately not done

- Reports for =shell= sessions. A shell has no agent lifecycle, and a
  human claiming a state already has =ghostherd-mark-state=
- =dead= as a reportable state. Liveness is the host's answer, and an
  agent still able to report is not dead
- An alias table so a renamed agent's stale =GHOSTHERD_SESSION= keeps
  working. That is a memory leak with a lookup in front of it; a respawn
  is the honest repair

* Phase 3.6 — One round trip per tick  *(done)*

Goal: make the cost of watching an agent independent of how many other
agents you are watching, and stop a wedged host from taking Emacs with
it.

The numbers and the three tmux behaviours this rests on are in
[[file:design.org][design.org]] under "What the poll path costs".

** What shipped

- [X] =ghostherd-backend-screens=: an optional slot capability for a host
  that can dump the whole herd's screens in one go, asynchronously.
  Returning nil --- which ghostel does, because its screens are already
  Emacs buffers --- keeps the old per-session read
- [X] The tmux implementor: =list-panes= plus a delimiter and a
  =capture-pane= per session, in one =make-process=, with stderr kept out
  of the screens and a random per-fetch delimiter
- [X] Six agents: 30.5 ms of blocking per tick → 6.1 ms, and N+1
  subprocesses → 1
- [X] The liveness snapshot rides along in the same round trip, so the
  poll path no longer makes a second synchronous call to ask
- [X] =ghostherd-tmux-fetch-timeout=: a host that stops answering is
  given up on and complained about once, rather than blocking Emacs in
  an uninterruptible =call-process= from a timer
- [X] A fetch never stacks on a slow server: the tick is skipped instead
- [X] =ghostherd--detect-state= and =ghostherd-poll-session= take the
  screen the batch already fetched; every interactive caller still reads
  for itself
- [X] 10 new ERT tests including a real-tmux batch round trip, plus pure
  seams for the argument list and the parse

** What is left

- [ ] Watch for a partial-batch pattern in daily use. A pane killed from
  outside is meant to cost one tick of individual reads; if that turns
  out to be common rather than rare, the fetch should ask =list-panes=
  first and capture only what it reported

** Deliberately not done

- Poll backoff for idle sessions. It was the obvious fix while the cost
  was per-session; batching removed the thing it fixed, and staleness
  is a real price with nothing left to buy
- Batching the *other* tmux calls (send, keys, options). They happen
  once per user action, not once per tick per agent

* Phase 3.7 — The log outlives Emacs  *(done)*

Goal: close the asymmetry Phase 3 opened. Agents survive an Emacs quit;
the record of what they did while nobody was watching did not.

Why the mechanism is shaped this way is in [[file:design.org][design.org]] under "Why the
log outlives Emacs".

** What shipped

- [X] =ghostherd-log-file= (on by default): every entry appended as it
  happens, read back when =ghostherd-mode= comes up, with a seam line
  saying how many entries came from the earlier Emacs
- [X] The kept =blocked= screens persist too --- they are the reason the
  log keeps anything, and 02:00 was always going to be on the far side of
  a restart
- [X] Appended per entry rather than saved on exit, because a
  =kill-emacs-hook= does not run for a crash. Verified with =kill -9=:
  new Emacs, same file, transition line and screen both intact
- [X] A plist per line rather than the struct, so a future slot cannot
  shift every line written before it
- [X] Compaction on read, so the file is bounded by one session's
  activity rather than by all of them
- [X] One warning and then memory-only if the file cannot be written ---
  the write happens per transition, so a read-only directory must not
  produce a message per transition
- [X] =ghostherd-log-clear= (=C= in the log buffer): quitting Emacs used
  to empty the log by accident
- [X] 9 new ERT tests (175 total), mutation-checked five ways

** What is left

- [ ] Watch the file size over a week of real use. The bound is "one
  session's activity", and if that turns out to mean megabytes then
  compaction wants a size trigger rather than only a start-up one

** Deliberately not done

- Persisting the *reports* table. A report is trusted for 120 seconds; one
  that outlived the Emacs it was made in should lose to the rules, which
  is what happens by not writing it down
- Persisting =seen=, the manual state or the OSC progress. Same reason as
  the recipe: they describe this Emacs's relationship with the agent, not
  the agent
- A log per project or per session. The herd log is the herd's, and
  filtering a buffer is a different feature from splitting a file

* Phase 3.11 — The sidecar answers only its token holders  *(done)*

Goal: close a hole Phase 3.8 opened and 3.9 widened.  Loopback kept
other machines out, not other origins: any web page could read the
transcript index or queue a prompt into an agent.  Why each layer is
there: "Why the sidecar wants a token" in [[file:design.org][design.org]].

** What shipped

- [X] =POST /jsonrpc/<token>=; =rpc.token= (0600) created by the
  sidecar on first start.  Agents' ="$GHOSTHERD_RPC"= calls unchanged
- [X] =application/json= only, no CORS middleware, loopback =Host= only
- [X] =/health= reports a =token_id= fingerprint, so Emacs tells its
  sidecar from a stale one in the request it already made; its own
  stale one is restarted, any other is named with the command to stop it
- [X] The token stays out of =*Messages*=, the uvicorn access log and
  error text; =rpc.url= is 0600
- [X] An old agent's bare URL gets a 401 pointing at =rpc.url=
- [X] 8 pytest and 4 ERT tests, each guard mutation-checked; plus a
  real sidecar attacked with curl the ways a page could

** What is left

- [ ] Agents spawned before this hold a bare =GHOSTHERD_RPC= until
  respawned; they recover through =rpc.url= if they follow the skill

- [X] Open at the hit, 160-chunk windows, Earlier / Later keeping the

- [X] Chunks joined back into messages, the overlap dropped
- [X] Sanitized markdown without images; agy plain; tool-call chips
- [X] The sidecar's source index answers from any worker thread: =SPC a

- [X] The page shows the sidecar's import progress, read every 5s
- [X] 14 ERT tests, 2 pytest; 38 WebKit checks against the real handler

* Phase 3.14 — Resume a past session from the page  *(done)*

* Phase 3.17 — Agents report through their hooks; the herd knows their conversations  *(done)*

Goal: state from the CLIs themselves rather than their screens, for all
three, without an Emacs server; and each agent's conversation and last
answer, for asks, respawn and the page.

** What shipped

- [X] =herd hook [EVENT]=: claude, grok and agy payloads to state,
  conversation, transcript and last answer; fails open, silent
  outside the herd, =working= at most every 30s
- [X] =herd hooks install|uninstall|status [--dry-run]= and
  =ghostherd-install-hooks=: adds to =~/.claude/settings.json= (claude
  and grok) and =~/.gemini/config/hooks.json= (agy), backs up, dry run
  shows only the entries it adds
- [X] =herd_report= on the sidecar; reports to Emacs on the tick through
  =ghostherd-report=; links kept by the sidecar and sent each tick
- [X] =herd hooks list= and the Agents tab's hook list: every hook each
  CLI runs, where it lives, ghostherd's marked; a click opens the file
  at the line (by index -- the page never names a path)
- [X] An unanswered ask closes with the taker's last answer
- [X] Respawn resumes the exact conversation; =ghostherd--resumed-by=
  trusts the hooks; explain and the Agents tab show the conversation
  and the last answer
- [X] 25 pytest (every CLI's payloads, transcripts read from the tail,
  the installer on a fake home, the hook inventory), 12 ERT, 9 more
  end-to-end checks, WebKit checks of the hook list and of a page with
  nothing installed; each guard mutation-tested

** What is left

- [ ] Run the hooks on the real CLIs for a few days: whether claude's
  transcript holds the last answer by the time =Stop= fires is the one
  thing the tests cannot answer, and a =Stop= that beats it costs only
  the screen fallback
- [ ] agy has no permission event; its =blocked= is still the screen's

* Phase 3.18 — A project's room: its agents' conversations side by side  *(this tree)*

Goal: follow two or more agents working one thing together --- one
builds, one tests, back and forth --- as one conversation, on the page.

** What shipped

- [X] A project's name on the Agents tab opens its room: a column per
  agent, its transcript as turns --- yours, the herd's (an ask or an
  answer, named, in the other agent's colour), its own, tool calls
  folded --- with a prompt box, Esc, 1 / 2 / 3 and Screen per column
- [X] =herd_conversation= on the sidecar: the tail of a claude, agy or
  grok transcript as entries, further back until there are enough;
  cached by size and mtime; only under the CLIs' transcript directories
- [X] =ghostherd-session-transcript=: the hooks' transcript, else the
  conversation the agent was started on, located by each kind's
  =:transcript= pattern; a miss is looked for again after 30s
- [X] Emacs stats the room's transcripts every 2s and asks only about
  one that changed; an agent without one sends its screen
- [X] 20 pytest (each CLI's records, the herd's framing read from
  =ghostherd.el= and the sidecar's mail, herd client calls, the path
  guard, the tail, the cache), 8 ERT, an end-to-end run on a real
  sidecar with a fake home, WebKit checks of the room; each guard
  mutation-tested

** From the first QA ↔ RD run

- [X] An ask pasted into claude arrived wrapped in =<pasted_content>=
  and read as yours; the room now reads the framing inside it
- [X] An =ask --wait= run in the background showed Claude Code's
  "running in background" as the answer; the ask now waits for the
  call that reads its output, and a failed client call shows as a
  failure with its error.  =herd ask --help= is no longer an ask
- [X] The room read an answer only when Claude Code's end-of-output
  marker ended the text; an asker that ran more after =cat= (rd did)
  left its asks waiting forever

** What is left

- [ ] The loop itself: two agents handing work back and forth until
  one says it is done --- today each turn is an ask the agent decides
  to make; a herd-run loop (who goes next, when it stops, a turn cap)
  is the experiment this room was built to watch
- [ ] Earlier turns: the room shows the tail; the whole conversation is
  on the Sessions tab once imported

* Phase 3.19 — An image in a prompt  *(this tree)*

Goal: show an agent a screenshot from the page, whichever CLI it is.

** What shipped

- [X] ⌘V an image into any prompt box on the Agents tab or in a room,
  or /Image/ beside it: Emacs saves the clipboard's image and the
  file's name goes where the cursor was
- [X] =ghostherd-save-clipboard-image=: the first of
  =ghostherd-clipboard-image-commands= installed (=pngpaste=,
  =wl-paste=, =xclip=), checked to be a PNG, written byte for byte,
  mode 600 in a 700 directory; images older than
  =ghostherd-image-keep-days= go when the next is saved
- [X] 4 ERT, WebKit checks of the paste, the button and where the name
  lands; each guard mutation-tested
