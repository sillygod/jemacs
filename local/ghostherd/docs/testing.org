#+TITLE: ghostherd — testing

How the suite is built and what still needs a human. The manual is
[[file:../readme.org][readme.org]].

* Automated (=ghostherd-tests.el=)

#+begin_src bash
  cd local/ghostherd
  emacs --batch --init-directory=~/.emacs.d/emacs-home/ \
        -L . -l ghostherd.el -l ghostherd-tests.el \
        -f ert-run-tests-batch-and-exit

  cd server && uv sync --extra dev && GHOSTHERD_MEMORY_FAKE_EMBED=1 uv run pytest
#+end_src

The sidecar tests live in =server/tests=. They never download FastEmbed:
=GHOSTHERD_MEMORY_FAKE_EMBED=1= hashes tokens into vectors. That is
enough to pin "import then search finds overlapping terms" and "grok
recap_requests is not a source". A real ranking check is a dogfood pass
after the first import of this machine's corpus.

Covers the parts that need no PTY: rule matching and precedence, OSC
progress freshness and handler chaining, state-detection precedence, sidebar
column fitting, title filtering, naming and age formatting.

Phase 3.6 moved the poll path to one batched, asynchronous round trip
per host. Two pure seams make that testable without a process: the tmux
argument list (=--screens-args=) and the parse (=--parse-screens=). The
tolerant-parse test is the one to keep honest --- tmux abandons a command
list at the first failure, so a partial answer is normal input, not an
error case.

Phase 3.5 added the report authority, and the tests to reach for when
editing detection are the precedence ones: which authority wins is now a
five-row table (readme, "Agents that report themselves"), and every row
has a test. The two that look like oddities are load-bearing --- a
=working= screen vetoing a claimed =blocked=, and a report never being
polled synchronously.

Phase 3 added the host slot, and the way it is tested is the point: a
=fake= backend answers with a known screen, so the tests pin the *call
sites* rather than either implementor. Rewiring detection back to a
buffer fails a test with no tmux and no PTY anywhere near it. For tmux
itself, =ghostherd-tmux--call= is the single seam every invocation
passes through, so stubbing it pins the actual command lines --- which
is where this backend's mistakes live: a missing =\==, a =paste-buffer=
without =-r=, a =capture-pane= that grew a =-J=.

One test runs against a real tmux (spawn → capture → send → restore →
kill) and is skipped when tmux is absent. It is the only thing that
would catch tmux changing its mind about a flag.

The suite was mutation-checked rather than merely run. Breaking the
blocked-beats-progress rule, the progress chaining, the column budget,
the mandatory-column flag and the title filter each fail a test; so do
marking a detached view as =dead=, dropping the exact-target =\==,
joining wrapped lines in a capture, letting =paste-buffer= turn
newlines into submissions, hashing a project root with and without its
trailing slash, and letting restore clobber a session it already knows.

That exercise has now found two real defects. The first was a floor on
the column budget that made the mandatory flag unreachable. The second
was an off-by-one in the new screen tail: a capture of exactly N rows
ends in a newline, so splitting it yields N+1 fields and taking the
last N drops the *first* line --- which is how the first thing an agent
printed goes missing from a screen that is plainly still showing it.

* Manual

The interactive spawn/kill paths still need a human, since driving real
ghostel PTYs headlessly is what Phase 1 deferred. Run after reloading config
(or restarting Emacs) so =local/ghostherd= and leader keys are loaded.

* Prerequisites

1. =ghostel= package installed and working (=M-x ghostel= opens a shell).
2. CLIs on =PATH=: =claude=, =grok=, =agy= (skip kinds you do not have).
3. =tmux= on =PATH= for T10–T13 (developed against 3.5a; identity
   injection needs 3.2+, and degrades with a warning below that).
4. =alert= available (this config sets =alert-default-style= to =osx-notifier=).
5. =jemacs-ai= loaded so =use-package ghostherd= ran; first command will load the package and enable =ghostherd-mode=.

* Smoke (load / compile)

In a shell:

#+begin_src bash
  cd ~/.emacs.d/local/ghostherd
  emacs --batch --init-directory=~/.emacs.d/emacs-home/ \
        -L . -f batch-byte-compile \
        ghostherd-backend.el ghostherd-tmux.el ghostherd.el
#+end_src

Expect: no errors (warnings about free vars from ghostel internals are OK if any).

In Emacs:

#+begin_src emacs-lisp
  (require 'ghostherd)
  (ghostherd-mode 1)
  (featurep 'ghostherd)   ; => t
#+end_src

* Manual test plan

Run each row; mark pass/fail. Prefer a real project directory so project
filter and buffer names look right.

** T1 — Spawn single agent

| Step | Action                                      | Expected                                      |
|------+---------------------------------------------+-----------------------------------------------|
| 1    | =SPC a h n= (or =M-x ghostherd-new=)        | Prompts kind / name / dir / args / notes      |
| 2    | Kind =claude=, name =t1-claude=             | Buffer =*ghostherd:t1-claude*= appears        |
| 3    | Wait ~1–2s                                  | CLI starts (not stuck forever at bare shell)  |
| 4    | Repeat for =grok= and =agy= if installed    | Same for each kind                            |

Failure modes: spawn delay too short → raise =ghostherd-spawn-delay=;
command not found → fix PATH for Emacs (login shell / exec-path).

** T2 — Sidebar + switch

| Step | Action                         | Expected                                      |
|------+--------------------------------+-----------------------------------------------|
| 1    | =SPC a h b=                    | Centred posframe =*ghostherd*= (or a side window if posframe cannot display) |
| 2    | Move to a row, =RET=           | Overlay closes; focuses that agent buffer     |
| 3    | =SPC a h s=                    | Completing-read lists agents with state glyph |
| 4    | =g= in the list                | Rows refresh without error                    |
| 5    | =SPC a h b=, then =Esc=        | Overlay / side window dismissed; layout unchanged |
| 6    | =/= then =agy=                 | Rows narrow; footer shows =/agy= and =N/M=        |
| 7    | =n= / =p=, then =RET=          | Moves among matches; visit closes the overlay     |

** T4 — State detection

| Step | Action                                          | Expected                          |
|------+-------------------------------------------------+-----------------------------------|
| 1    | Ask agent to do a short task                    | Sidebar/state → =working= (⟳)     |
| 2    | Trigger a permission/approval prompt if possible | State → =blocked= (⚠)            |
| 3    | macOS notification on blocked                   | Banner via =osx-notifier=         |
| 4    | Finish task, leave session unfocused            | Eventually =done= (✓) or =idle=   |
| 5    | =SPC a h .=                                     | Jumps to blocked/done agent       |
| 6    | If detection wrong: =M-x ghostherd-mark-state=  | Manual override sticky until auto |

Screen rules are heuristic. Prefer *missed blocked* over *false blocked*.
Tune =:screen-rules= in =ghostherd-agent-specs= when a CLI UI changes.

** T5 — Inter-agent message

| Step | Action                                                        | Expected                                      |
|------+---------------------------------------------------------------+-----------------------------------------------|
| 1    | Have two live sessions (=implementer=, =reviewer=)            | Both in herd                                  |
| 2    | =SPC a h m= → target =reviewer=, body =hello from test=       | Text pasted into reviewer (submitted if configured) |
| 3    | Elisp: =(ghostherd-message "implementer" "reviewer" "ping" :submit t)= | Attributed header + body in reviewer     |
| 4    | =(ghostherd-read "reviewer" 40)=                              | String contains recent tail                   |
| 5    | =(ghostherd-prompt "reviewer" "Reply with pong only")=        | Prompt submitted                              |

** T10 — tmux backend, headless

This is the acceptance test for Phase 3. Everything below T10 is
exercised by ERT *except* attach, which needs the compiled ghostel
module and so has never run outside a real Emacs.

Set =(setq ghostherd-backend 'tmux)= first.

| Step | Action                                             | Expected                                             |
|------+----------------------------------------------------+------------------------------------------------------|
|    1 | =SPC a h n= → claude, name =t10=, =:display= on    | Buffer appears; the agent is *inside* tmux           |
|    2 | =tmux -L ghostherd list-sessions= in a real shell  | One =gh-<hash>-t10=                                  |
|    3 | Sidebar: state tracks the agent as usual           | Detection is now =capture-pane=, not the buffer      |
|    4 | =M-x ghostherd-explain=                            | Shows host id + backend, and the captured tail       |
|    5 | Kill the =*ghostherd:t10*= buffer                  | Row stays; switcher annotates it =detached=          |
|    6 | Sidebar =RET= on that row                          | Re-attaches; same conversation, nothing lost         |

Failure modes: no session at step 2 → tmux not on Emacs's =exec-path=;
status bar visible after attach → the generated config was not read,
check =ghostherd-tmux--config-file= and =tmux -L ghostherd kill-server=.

** T12 — Detach is not death

The bug this phase most had to avoid.

| Step | Action                                        | Expected                                  |
|------+-----------------------------------------------+-------------------------------------------|
|    1 | Attach a tmux-backed agent, set it working    | State =working=                           |
|    2 | Kill the buffer while it is still working     | *No* "exited" notification; state unchanged |
|    3 | Wait a poll or two                            | Still =working=, still detached           |
|    4 | Quit the agent CLI itself (=/exit=)           | *Now* =dead=, and the last screen is still capturable |

** T13 — Identity and self-reported state

Both halves of Phase 3.5, and the only part ERT cannot reach: whether the
variables really arrive in a process tmux exec'd, and whether a CLI's own
hook can drive the herd.

| Step | Action                                                    | Expected                                     |
|------+-----------------------------------------------------------+----------------------------------------------|
|    1 | In a spawned agent's shell: =ghostherd whoami=            | Its own session name                         |
|    2 | =ghostherd report self blocked "trying it"=               | Row turns =blocked= within a poll; banner    |
|    3 | =M-x ghostherd-explain=                                   | =reports blocked  trying it  (Ns ago…)=      |
|    4 | =ghostherd report self auto=                              | Back to whatever the screen says             |
|    5 | Wire claude's hooks (see readme), then answer a permission prompt | =blocked= on the question, =done= on Stop |
|    6 | From the other agent: =ghostherd message implementer hi=  | Arrives attributed to the *sender*, not "user" |
|    7 | Kill the hook config mid-session, leave a prompt open     | Row falls back to the rules within the TTL   |

Step 7 is the one worth doing deliberately: it is the failure mode the
TTL exists for, and the reason a report is not a =mark-state=.

** T14 — A host that stops answering

The failure the fetch timeout exists for, and the one ERT cannot stage:
=SIGSTOP= is the cheapest wedged server there is.

| Step | Action                                                       | Expected                                        |
|------+--------------------------------------------------------------+-------------------------------------------------|
|    1 | =pkill -STOP -f 'tmux.*-L ghostherd'= with a herd running     | Emacs stays responsive; no freeze on the timer   |
|    2 | Wait =ghostherd-tmux-fetch-timeout= (10s)                     | One warning; sidebar states stop changing        |
|    3 | Keep typing in an unrelated buffer for a while                | Still responsive, and only one warning total     |
|    4 | =pkill -CONT -f 'tmux.*-L ghostherd'=                         | States resume within a tick or two               |

Step 1 is the regression: before Phase 3.6 this hung Emacs in an
uninterruptible =call-process=, repeatedly, from a timer.

** T15 — The log outlives Emacs

ERT covers the file format; what it cannot stage is a real Emacs dying.

| Step | Action                                              | Expected                                          |
|------+-----------------------------------------------------+---------------------------------------------------|
|    1 | Run a herd until something goes =blocked=            | A =⏎= line in =SPC a h l=                          |
|    2 | =pkill -9 emacs= (no exit hooks run)                 | --                                                |
|    3 | Start Emacs, =SPC a h l=                             | Yesterday's lines, then "resumed N entries…"      |
|    4 | =RET= on the old =⏎= line                            | The screen that rule fired against, still there   |
|    5 | =C= in the log buffer                                | Log and file both gone                            |

Step 4 is the one that matters: it is the 02:00 rule the kept screens
exist for, read the next morning.

* Dogfood log

Screen rules are heuristics against a UI that changes between releases,
so record what was observed against which version.  Prefer a *missed*
=blocked= over a false one.  =M-x ghostherd-explain= is what produces
the evidence: it shows the scraped tail, every pattern that matched it,
and which one won.

| CLI    | Version tested | Known false positive / miss | Fix applied |
|--------+----------------+-----------------------------+-------------|
| claude |                |                             |             |
| grok   |                |                             |             |
| agy    | 1.1.13         | =Thinking= matches a model name in the =/model= picker | not yet |
| agy    | 1.1.13         | =^>= matched the transcript, not the prompt | =^> *$= |
| agy    | 1.1.13         | prompt is drawn while working too, so no prompt rule can mean idle | =ghostherd-idle-settle= |
| agy    | Gemini 3.1 Pro | substring =permission= matched JSON ="permissions"= after editing settings.json; agent was idle on =>= | =ghostherd--rule-permission-prompt= (word, not =permissions= / =permission-mode=) |

agy 1.1.13 identifies itself as "Antigravity CLI".  Under tmux it
repaints its whole UI on every SIGWINCH, so an attached window flickers
while dragged --- its own behaviour, not the nesting's; see "What the
tmux host costs" in [[file:design.org][design.org]].

Follow-up, same session: silencing the flood also silenced the one
notification that was wanted.  Being *displayed* was the wrong test --
=get-buffer-window= with ALL-FRAMES t counts iconified frames and other
desktops, so switching to a browser still counted as watching.  It is
now a window on a visible frame whose frame holds input focus.

The one that finished the argument, from the third pass.  Tightening
the prompt rule was right and not enough: agy draws its input prompt
whether or not it is working, so *no* rule about the prompt can mean
idle for this UI.  What makes its screen read as busy is a spinner, and
that blinks out between two tool calls --- a poll landing in the gap saw
nothing working, called it idle, promoted it to =done=, and notified.
Three seconds of that produced four "ready for review" banners.

So the fix is not a better rule but hysteresis: =ghostherd-idle-settle=
holds a busy session at its state until idle has stuck.  Entering idle
waits; leaving it is immediate, because something appearing on screen is
a positive signal.

Second finding in the same screenshot: every one of those banners was
about an agent visible in a window at the time.  =done= means "finished
while you were not looking", so a session on screen now counts as seen.

The one that mattered, from the log's second hour.  agy scrolls rather
than repaints, so every line you have ever typed stays on screen as
=> what you typed=.  The idle rule =^>= matched those, which means it
reported =idle= from the first time you pressed Return --- forever, and
regardless of what the agent was doing.  Combined with the idle→done
promotion, every prompt produced a =done= notification about a second
after it was sent.

The reason field said so out loud, which is what made it findable:

: state    ○ idle
: reason   execute date command      ← sent half a minute earlier

Fixed by anchoring to an *empty* prompt, =^> *$=.  Free to tighten,
because a prompt the rules fail to recognise falls through to the idle
default anyway.  claude's separator line and grok's banner were the same
category error --- frame, not state --- and are gone.

First finding, from the herd log's first hour: choosing a model with
=/model= lists =Claude Sonnet 4.6 (Thinking)=, and the =working= rule
=Thinking= matches it.  The agent is idle at a menu, the herd says
=working=, and the churn out of it fires a spurious =done= notification a
second later.  A rule anchored to how the status line actually draws it
--- =Thinking…= with the ellipsis, or leading whitespace --- would not.
Left alone deliberately: it is one observation, and the point of the log
is to collect several before touching thirty patterns.
