ghostherd · xwapp · tailscale serve

手機打開 herd page 時，誰擋誰

從手機到 Emacs，一個請求要過兩道檢查：網址裡的密鑰，以及「是誰在問」。這頁走一遍整條路，再逐一看各種闖入者走到哪裡被擋，或擋不住。

先說結論

擋得住

有人進了你的 tailnet，但用的是別人的身分（他自己的帳號、分享進來的裝置、tag 裝置）：就算他知道 host 和密鑰，Emacs 也回 404。擋下他的是「誰在問」那道，不是密鑰。

擋不住

有人用你的身分進來（偷了你登入 Tailscale 的帳號再加一台新裝置，或拿到你的手機）：xwapp 認不出他不是你。他甚至不需要知道密鑰，/open/ghostherd 會直接給他。這一層只能在 Tailscale 那邊補，見最後一節。

兩道檢查

Emacs 收到請求時看什麼

檢查 1 · 密鑰

網址裡有沒有對的密鑰

http://<tailnet 名稱>/3f9a…c41e/ghostherd/ui/index.html
  • 每個 app 一把：herd page、pr-view、clickup-view 各自不同
  • 16 個隨機位元組，寫成 32 個十六進位字元
  • 錯的或沒有 → 404
  • 存在 emacs-home/xwapp-browser.eld，只有你讀得到；有設手機 hosts 時重開也保留
檢查 2 · 誰在問

看傳輸來源和身分

  • 本機來的（走 loopback port）：Host 必須是 127.0.0.1:48123 或 localhost:48123，Origin 要嘛沒有、要嘛就是它自己。別的網站的網頁改不了 Host，也假造不了 Origin
  • 手機來的（走 unix socket）：Tailscale-User-Login 必須是你的登入（xwapp-remote-users 之一）。serve 轉給 socket 時把 Host 改寫成 localhost，所以 Host 不看——走哪條路才是證明。頁面自己的呼叫會帶 Origin，必須是 xwapp-remote-hosts 之一（你的 tailnet 名稱），擋掉手機上別的網站
  • 判斷是哪一種，看的是請求從哪個監聽進來，不是標頭：標頭能假造，走哪條路不能。只有真的從代理轉來的，才可能算「手機來的」
  • 兩種都不是 → 404

唯一的例外：/open/<app>

這個位址不需要檢查 1，只看檢查 2，而且只接受「手機來的」那種——也就是只在 unix socket 上回應。通過了，Emacs 回一個轉址，帶你到含密鑰的完整位址。換句話說，密鑰只交給真的經代理、從 tailnet 進來的瀏覽器。所以這個位址可以放進書籤，也可以放進 Telegram：Telegram 的伺服器會保存訊息，但看到這個連結的人不在你的 tailnet、不是你，就拿不到任何東西。

兩種打開方式

實際走一遍

點 Telegram 的按鈕，或書籤

  1. 手機打開 http://<tailnet 名稱>/open/ghostherd#agents
  2. 經隧道到 Mac 的 tailscale serve，它填上你的登入
  3. Emacs 看傳輸來源和登入檢查 2
  4. 通過 → 回 302，轉到 /<密鑰>/ghostherd/…#agents
  5. 瀏覽器照轉址再要一次，這次兩道都看檢查 1·2
  6. 頁面打開，之後每個請求都帶著密鑰

掃 Phone 按鈕的 QR code

  1. QR code 裡就是含密鑰的完整位址（所以只在你按了才顯示）
  2. 手機打開它，經隧道到 tailscale serve，填上你的登入
  3. Emacs 兩道都看檢查 1·2
  4. 頁面打開

密鑰換掉（M-x xwapp-renew-secret）後，這種含密鑰的書籤會失效；/open/ 的不會。

所以密鑰到底在擋什麼

密鑰實際擋的是什麼

密鑰主要擋的是你 Mac 瀏覽器裡的網頁：它們送得到 127.0.0.1，但不知道密鑰，也假造不了身分。對從 tailnet 進來的人，真正把關的是檢查 2，而檢查 2 只分得出「是不是你這個帳號」，分不出「是不是你的哪台裝置」。

Agent 回覆裡提到的圖片也走同一條路：herd page 只用一個猜不到的 id 拿它（/密鑰/.files/<id>.png），在密鑰底下、經過同樣兩道檢查才給；沒有任何「給路徑就讀檔」的位址——頁面既然手機打得開，那種位址等於把整個硬碟交出去。

對用你身分進來的人，密鑰不算數，因為 /open/ 會把它交出去。這是一個取捨：換來的是可以放書籤、可以放 Telegram 的位址。常有的誤解是「在 tailnet 上的人沒有密鑰就用不了頁面」：對用你身分的人並不成立。

曾有的一個缺口：本機程式能假造身分（已修補 2026-10-16）

原本 tailscale serve 也是從 127.0.0.1 連到 Emacs，Emacs 分不出一個連線是代理轉來的，還是這台 Mac 上任何程式自己連的。實測過（2026-10-13）：直接連 127.0.0.1:48123，自己填上 tailnet 的 Host 和你的登入，/open/ghostherd 就回 302 並給出密鑰。

修法是讓代理改轉到一個 unix socket（xwapp-remote-socket），Emacs 同時聽那個 socket 和原本的 loopback port。只有從 socket 進來的請求才算「手機來的」、才回應 /open/；loopback port 只服務本機瀏覽器。socket 和它的資料夾都設成只有你能開，所以別的帳號開不了它，只碰得到本機網路的沙盒也定址不到它。標頭能假造，走哪條路不能——這就是現在用來分辨的依據。用 M-x xwapp-remote-serve-setup 把代理指到 socket。

擋不住的仍是「本來就是你」的程式：和你同一個使用者、又能讀到 socket 檔案路徑的，跟你本人無異（它本來就能用 emacsclient 讓 Emacs 跑任何程式碼）。這超出「分辨請求從哪裡來」能處理的範圍。

你的設定

看自己的 tailnet 現在是什麼狀態

  • tailscale status：tailnet 上有哪些裝置、各是誰的。只有你自己的裝置時，表格裡「別人的裝置」那列不會發生
  • tailscale lock status：Tailnet Lock 有沒有開
  • tailscale serve status：herd page 是不是只開給 tailnet（tailnet only），轉到哪個 port
  • Tailscale 管理頁：裝置金鑰會不會到期、新裝置要不要核准

只有你自己的裝置時，最實際的威脅是表格裡紅色那兩列：有人拿到你登入 Tailscale 的帳號、自己加一台裝置進來，或拿到你的手機。

怎麼補

依效果排序

  1. 最重要

    開 Tailnet Lock

    開了以後，新裝置就算登入的是你的帳號，也要由你現有的裝置（這台 Mac、你的手機）簽過才能加入 tailnet。這直接堵住「偷了帳號、加一台新裝置」那條路，也就是 xwapp 本身擋不住的那一列。

    用 tailscale lock status 看兩台裝置的金鑰，再照 Tailscale 文件用 tailscale lock init 把它們設為信任的簽署者。設定時會產生一組解除用的 disablement secret，要另外妥善保存。

  2. 接著

    你登入 Tailscale 用的帳號開兩步驗證

    Tailscale 的身分來自那個帳號（例如 Google）。帳號被盜，就是表格裡「用你的身分加進來」那一列的起點。

  3. 手機遺失時

    先在 Tailscale 管理頁移除那台裝置，再換密鑰

    移除後它就進不了 tailnet。再跑 M-x xwapp-renew-secret，讓書籤和紀錄裡的含密鑰位址失效。

  4. 選擇性

    用 ACL 限定只有你的手機能連 Mac 的 80 port

    將來 tailnet 上多了別的裝置，它們連 herd page 的門口都碰不到。

  5. 已完成

    本機假造身分的缺口已補（2026-10-16）

    代理改轉到一個只有你能開的 unix socket，Emacs 只把從那個 socket 進來的請求當成代理轉來的。走哪條路不能假造，標頭能。見上方「密鑰實際擋的是什麼」。
