#+TITLE: clickup-view

ClickUp inside Emacs: read a task (description, checklists, subtasks,
attachments, comments and their threads), change its status, dates and
assignees, comment and reply, and browse Space ▸ Folder ▸ List.  Built on =xwapp=: Elisp owns
HTTP and the token, =ui/= only renders.

* Status

| Item    | Value |
|---------+-------|
| Package | =local/clickup-view/= |

* Auth

=CLICKUP_API_TOKEN=, a personal token (=pk_...=), sent in =Authorization=
bare, without =Bearer=.  GUI Emacs does not read shell rc files, so set
it in =settings.el= as =BITBUCKET_TOKEN= is:

#+begin_src emacs-lisp :tangle no
  (setenv "CLICKUP_API_TOKEN" "pk_...")
#+end_src

The workspace is the token's first; set =clickup-view-team-id= to pick
another.

* Finding the task

=clickup-view= and =clickup-set-status= read the branch name and the
commits not yet on the remote default branch (=origin/HEAD=, else
=origin/main=, =master=, =develop=; at most =clickup-view-scan-commits=)
for =app.clickup.com/t/<id>= links and =CU-<id>=.  An id has a digit
(every one sampled does, 9--10 characters): =CU-ids= in prose is a word,
not a task.  One task opens
directly, several are offered with where each was found, none opens the
browser (=clickup-view=) or asks (=clickup-set-status=).  =C-u M-x
clickup-view= always opens the browser.

* What ClickUp actually sends

Probed against the workspace, October 2026.

- Statuses belong to a list, not a space: BACKLOG has Open / in progress
  / testing / wait for testing / ready to release / Closed while its
  space's default is to do / in progress / complete.  Read from
  =GET /list/{id}= and cached for the session.
- Comments are Quill delta ops, not markdown: newest first, 25 a page,
  older ones via =start= + =start_id=.  Op types seen: =text=, =image=,
  =divider=, =table-embed=, =tag= (@mention), =task_mention=,
  =link_mention=, =view_mention=.  A =table-embed= cell is its own small
  delta under =content=, keyed ="row:col"=.
- They become HTML in Elisp, not in the page: the page can issue intents
  (change a status, post a comment), so a comment must never reach it
  unescaped.  Every text run is escaped and only http(s) / mailto links
  survive.
- Replies: =GET /comment/{id}/reply=, same shape, newest first.
- Outgoing comments and replies are markdown converted to delta ops ---
  a port of the clickup-task-manager skill's =markdown_delta.py=, tested
  op for op against its output.  ClickUp stores =comment_text= verbatim,
  raw =**= and all.  Replies send the same body as task comments; that
  has not yet been exercised by a live write.
- 401 is not always the token: a task id outside the workspace, or one
  that does not exist, is =Team not authorized= (=OAUTH_027=).  A bad
  token is =Token invalid= (=OAUTH_025=).
- Attachment images (=*.clickup-attachments.com=) load without auth.
- A list's tasks come 100 a page, subtasks included as rows of their
  own (=parent= set), newest created first.  A parent and its subtasks
  arrive on the same page.  BACKLOG: 70 top-level + 47 subtasks, two
  pages; 34 of the 47 have a status other than their parent's.
- A list's =task_count= is its open top-level tasks.
- Status types: =open=, =custom=, =done=, =closed=.  =done= is not
  closed: BACKLOG's "wait for testing" is one.  =include_closed= adds only
  =closed=.
- A date is ms; =due_date_time= / =start_date_time= say whether its
  time of day counts.  A day with no time is kept at 4 in the morning,
  local: a due date set in ClickUp to Oct 12 is =2026-10-12 04:00 CST=.
  Null clears a date.
- Who can be given a list's tasks: =GET /list/{id}/member= (BACKLOG: 30).
  Assignees change by =PUT /task/{id}= with ={"assignees": {"add": [...],
  "rem": [...]}}=, numeric user ids.

* The page

=ui/index.html=, =app.js= and =style.css=, on xwapp's page kit
(=../../xwapp/ui/=: the intent bridge, the sanitizer, the colours, and
marked 11.2.0 --- identical to jsdelivr's; vendored because jwebkit's copy
is a gitignored download that may not exist yet).

Views: home (open a task by link, the spaces), a space (its folderless
lists first, then each folder's), a list, a task.  The breadcrumbs go
up from any of them; a folder crumb opens its space at that folder.
=CU= goes home.

- A list groups its tasks by status, in the list's own order.  Subtasks
  fold under their parent (→ / ← or the chip); a subtask whose parent
  is not shown (Mine) stands alone, marked ↳.  The filter matches names
  and ids (a link or CU-id works) and shows every match flat.  Mine and
  Closed load the list again and carry over to the next list.
- The page fetches a list's pages itself, up to 5 (500 rows), so status
  counts and the filter see the whole list; past that, Load more.
- Going forward always loads fresh.  Back shows a space or list as it
  was left, at the same scroll, with the row of the task just left
  focused; a task loads again.  A status, due date or assignee changed
  here updates the lists the page keeps.
- Assignees and the start and due dates open an editor under them, as
  the status does.  Assignees: who has the task, you, then the list's
  people by name, a box to find one when there are more than 8; a tap
  gives or takes the task, the menu staying open.  A date: a day, Today,
  Tomorrow, In a week, Clear.  A day picked keeps the time of day the
  date had; a date that had none gets 4 in the morning where you are,
  as ClickUp does.
- Only closed tasks are muted.
- Keys: =s= status menu (arrows, Enter, Esc), =a= assignees (type to
  find, Enter gives the first), =d= due date, =r= refresh, =Esc= back,
  =/= filter, =↑= / =↓= between rows, =→= / =←= subtasks, =⌘↩= / =C-↩=
  sends the comment or reply being typed.
- Comments are newest first with the composer on top; a thread reads
  oldest first.  Drafts survive re-renders and moving between tasks.
- Every link is caught: a task link (or =data-task=) opens in the page,
  anything else http(s) / mailto goes to =browse-url=.  Left alone, a
  click would navigate the xwidget away from the page and its bridge.
- The description is ClickUp's markdown through marked, then a
  whitelist sanitizer (inert =DOMParser= document; allowed tags and
  attributes only, http(s) links, no inline styles).  Comment HTML from
  Elisp is already escaped and passes through the same sanitizer.
- A Content-Security-Policy behind the sanitizer: no inline script or
  handler, no =javascript:= link, no fetch; images https or data:.

* On your phone

From the herd page on your phone, or from pr-view there, a task opens
in clickup-view's page there --- through xwapp's address without the
secret, =/open/clickup-view#task=<id>=, the ClickUp token staying in
Emacs.  The page says which task once it loads (=ready= with =task=: an
id, a CU-id or a task link), and keeps the task on screen in its
address, so a reload, or Emacs restarted (=clickup-view-reopen=),
comes back to it.  Open and the links in a task open in a tab of the
phone, Copy copies to its clipboard.  Under 640 points the bar is one
line, its buttons their first word, with where you are --- space and
list --- on a line under it; to a finger, controls 32 points and more,
form text 16px.  The editors' menus move left rather than run past the
edge, and the people box does not pull up the keyboard by itself.

* Page contract

Intents, page → Emacs, as =document.title = "clickup:" + JSON=.  The
page queues them and sets the next title only after Emacs has reset the
last one: a title replaced within a poll interval is never read.  Each
carries a counter =n=, seeded from the clock: =xwapp= ignores a title
identical to the last one, so a second Refresh would otherwise be
dropped, and a reloaded page's first intent mistaken for the old one's.

| op               | fields                           |
|------------------+----------------------------------|
| =ready=          | task (from the page's address)   |
| =refresh-spaces= |                                  |
| =open-space=     | id, force                        |
| =open-list=      | id, page, closed, mine           |
| =open-task=      | id (also a link or CU-id)        |
| =more-comments=  | task_id, start, start_id         |
| =load-replies=   | comment_id                       |
| =set-status=     | task_id, status                  |
| =members=        | list_id                          |
| =set-date=       | task_id, field (due / start),    |
|                  | at (ms, null clears), time       |
| =set-assignees=  | task_id, add, rem (user ids)     |
| =post-comment=   | task_id, text (markdown)         |
| =post-reply=     | task_id, comment_id, text        |
| =open-browser=   | url (http(s) / mailto only)      |
| =copy-url=       | url                              |

Calls, Emacs → page, as =CU.fn(payload)=:

| fn              | payload                                                       |
|-----------------+---------------------------------------------------------------|
| =flash=         | message                                                       |
| =showError=     | message                                                       |
| =setContext=    | me, team, spaces                                              |
| =showHome=      |                                                               |
| =renderSpace=   | id, name, color, folders (each with lists), lists             |
| =renderList=    | id, name, statuses, space, folder, page, last_page, closed,   |
|                 | mine, tasks                                                   |
| =renderTask=    | task, statuses (null until =setStatuses=)                     |
| =setStatuses=   | list_id, statuses                                             |
| =setComments=   | task_id, items (newest first, with html), has_more, append    |
| =setReplies=    | comment_id, items                                             |
| =statusChanged= | task_id, status                                               |
| =setMembers=    | list_id, members                                              |
| =taskChanged=   | task_id, assignees, due, due_time, start, start_time; field   |
|                 | (the date changed) or users (who was given or taken it)       |
| =posted=        | task_id, comment_id (null for a comment): clear that box      |

Every payload names its space, list, task or comment.  The page drops
one that is not for what it is showing or on its way to, so a slow
reply for one task cannot paint over the next; a list page also has to
match the Mine / Closed it was asked with.  =folder= is null for a
folderless list.

* For other packages

pr-view uses these to show the tasks a PR cites; they are the public
surface, everything with =--= is not.

| Function                  | Does                                                   |
|---------------------------+--------------------------------------------------------|
| =clickup-view-task-refs=  | task ids a text cites, in order: links and =CU-<id>=   |
| =clickup-view-task-brief= | one =GET /task/{id}=; calls back with name and status, |
|                           | or with =error= (the token missing included)           |
| =clickup-view-task=       | open a task in the page (id, link or =CU-<id>=)        |

A brief never touches the page.

* Tests

The Elisp layer, against stubbed HTTP and page calls:

#+begin_src sh
  emacs --batch -L ~/.emacs.d/local/xwapp -L ~/.emacs.d/local/clickup-view \
        -l clickup-view.el -l clickup-view-tests.el \
        -f ert-run-tests-batch-and-exit
#+end_src

The page was checked in WebKit (Playwright) against this Elisp running
in a batch Emacs on the live API, writes faked.  Task page: status menu,
threads, posting, paging, subtask and Back, links, a hostile description
and comment, a 760px window.  Browser: home, space, a list's two pages,
status groups, subtasks, filter, Mine / Closed and quick toggles, Back
from the page's copy, breadcrumbs, stale replies dropped.  Not part of
the suite: it needs a browser and the token.
