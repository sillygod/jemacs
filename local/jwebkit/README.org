#+TITLE: jwebkit

Vim-like keys for Emacs =xwidget-webkit=.  Search, link hints, and
typing into the page.  Does not use =document.title= (that belongs to
=pr-view=).

* Status

| Item    | Value |
|---------+-------|
| Package | =local/jwebkit/= (straight =:local-repo=) |
| Wired in | =jemacs-ux= after =evil-collection= |
| Needs   | GUI Emacs with xwidgets |

=evil-collection= already maps hjkl / H L / o r yy / C-d C-u / zoom.
This package fills the TODOs it left: find, =f=, edit-mode.

* Keys (normal)

| Key | Command |
|-----+---------|
| =/= =n= =N= | in-page search (=window.find=; NS =xwidget-webkit-search= is a stub) |
| =*= | search for the current selection |
| =f= | ace hints, click |
| =F= | ace hints, open =<a>= in a new session |
| =gf= | pick a visible link with completion |
| =i= | send keys to the page (forms, PR comments). ESC / C-g back |
| =gi= | focus first input, then edit |
| =Y= | yank the page selection |
| =&= | open current URL in the system browser (a PDF opens its source) |
| =gp= | PDF: go to page |
| =gO= | PDF: toggle outline (thumbnails if the PDF has none) |
| =gr= | Markdown: reload the current preview |

Existing collection bindings stay: =j k gg G d u H L r yy o t x= …

* Keyboard focus after killing a page (macOS)

After a click in a page, killing its buffer (=SPC b d=) used to leave
the keyboard with nobody: Esc beeped and Emacs saw no keys until a
click on Emacs.  A click makes WebKit's view the window's first
responder, and =nsxwidget_kill= removes that view without handing it
back.  No Lisp primitive sets the first responder; the one path that
does is xwidget's own C-g message from the page.  So
=jwebkit--give-focus-back= (on =kill-buffer-hook=, which runs before the
xwidget dies) posts it and lets the run loop deliver it.

Only for a page in the selected window with a live view, and nowhere
else: the handler reads the view pointer, NULL once the view is gone,
and posting then would crash Emacs.  The wait does not redisplay, so
the view cannot go in between.  Switching away from a page is fine:
redisplay only moves its view off screen (=nsxwidget_hide_view=), where
it stays first responder and passes keys it does not use on to Emacs.

* PDF (pdf.js)

WebKit's own PDF view is a plugin with no DOM, so =/ f Y= do nothing
in it.  =jwebkit-pdf.el= reopens PDFs met in xwidget with pdf.js, whose
text layer is DOM: those keys work again, and =/= goes through pdf.js's
find so it also sees pages not rendered yet.

- =M-x jwebkit-open-pdf= opens a file or URL (=C-u= for a new session).
- The first use asks to download the pdf.js dist (~7 MB) into
  =emacs-home/jwebkit/pdfjs/<version>-legacy/=; =M-x jwebkit-pdf-install=
  does it by hand.  Not in git.
- =jwebkit-pdf-build= defaults to =legacy=.  xwidget renders with the
  system WebKit, not Safari's latest: on macOS 15.0 (WebKit 20619) the
  modern build's =pdf.mjs= dies on =Iterator= and leaves an empty
  toolbar.  The shim also polyfills =ReadableStream= async iteration,
  which that WebKit lacks and the legacy build does not cover; without
  it find and text extraction fail.
- A loopback server (127.0.0.1 only) serves the viewer and the PDF
  from one origin; a file:// viewer can fetch neither.  PDFs are served
  by random token, never by path.
- =jwebkit-pdf-port= nil (default) lets the OS pick a free port.  A set
  port that is taken falls back to a free one.  Binding is the check,
  so there is no probe-then-bind race.
- Remote PDFs are downloaded by Emacs, which does not have WebKit's
  cookies.  A PDF behind a login comes back as HTML and stays in
  WebKit's view.
- NS xwidget has no response hook, so WebKit's view flashes before
  pdf.js takes over.  =jwebkit-pdf-auto= nil turns the takeover off.
- Local =.pdf= files opened with =find-file= are left alone.

* Markdown (GFM + Mermaid)

Preview Markdown in xwidget with full GitHub Flavored Markdown and
=```mermaid= fences.  Same loopback pattern as the PDF viewer: a
file:// page cannot fetch local libs or the document.

- =M-x jwebkit-open-markdown= opens a file, or the current Markdown
  buffer (unsaved edits included).  =C-u= for a new session.
- The first use asks to download pinned =marked=, =mermaid= (UMD 10.x)
  and =github-markdown-css= into
  =emacs-home/jwebkit/md-libs/<pin>/=; =M-x jwebkit-md-install= does it
  by hand.  Not in git.  Offline after install.
- Shipped viewer: =md-viewer/viewer.html= (+ CSS/JS) in the package.
  Libs are served from the loopback server at =/md/libs/…=.
- A loopback server (127.0.0.1 only) serves the viewer, libs, and
  Markdown by random token, never by path.  File tokens re-read the
  file on each request (save, then =r= / =gr=); buffer tokens use the
  live buffer string.
- Dark/light follows =prefers-color-scheme=; mermaid's theme matches.
  In-page =/= search uses =window.find= on the rendered HTML.
- Versions default to marked 11.2.0, mermaid 10.9.3, github-markdown-css
  5.8.1 — UMD builds chosen for older system WebKit (xwidget).
- =jwebkit-md-port= nil (default) lets the OS pick a free port, same
  bind-is-the-check behaviour as PDF.
- Local =.md= files opened with =find-file= are left alone.

Manual fixture: =fixtures/gfm-mermaid.md= (table + mermaid).
